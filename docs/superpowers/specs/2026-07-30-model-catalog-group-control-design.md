# 模型广场分组可见性控制设计

## 状态与范围

- 日期：2026-07-30
- 状态：设计已确认，等待实施计划
- 作用范围：本地源码、本地数据库和本地验收环境
- 明确排除：生产部署、远端推送和 GitHub Release
- 本文取代并扩展 `2026-07-29-model-catalog-visibility-design.md`。旧设计中“所有分组始终公开”的结论不再成立；“公开但用户无权使用的分组保持锁定可见”继续成立。

## 目标

管理员在系统设置中维护一套全站统一的模型广场分组可见性策略。控制单位是整个分组，不是模型、渠道或用户：

- 默认所有当前及未来分组均可在模型广场展示。
- 管理员可以切换为指定分组白名单，并一次性隐藏或显示整个分组。
- 隐藏分组的标识、说明、模型关联和价格不得由公开定价接口下发。
- 模型只要属于至少一个可见分组就可以展示，但响应中的关联和价格只能覆盖可见分组。
- 可见但当前用户无权使用的分组继续显示锁定状态、模型和价格。
- 本功能只影响模型广场目录，不改变 Relay/API 调用权限、渠道选择、分组授权或实际计费。
- Sub2API 自动发现但尚未显式定价或分配分组的模型保持隐藏。

## 非目标

- 不提供单模型隐藏开关。
- 不提供按用户、角色、渠道或前端主题分别配置的可见性。
- 不把模型广场配置作为 API 权限边界，也不自动修改用户可用分组。
- 不改变模型倍率、分组倍率、特殊分组倍率或渠道能力数据。
- 不让 Sub2API 模型发现自动创建公开价格、公开分组或模型广场条目。

## 术语与不可变规则

- **分组全集**：后端从分组倍率配置和启用能力中的显式分组标识构建的管理集合；排除空字符串以及 `all`、`auto` 等内部哨兵值。
- **可见分组**：分组全集经过全局模型广场设置裁剪后的集合。
- **可用分组**：当前用户真实拥有调用权限的分组集合，仍由现有授权逻辑计算。
- **锁定分组**：属于可见分组，但不属于当前用户可用分组的分组。
- **目录投影**：从原始定价缓存派生的、只包含公开模型广场数据的不可变快照。

以下规则必须始终成立：

1. 隐藏不等于禁用；隐藏分组的合法 API 调用继续按原有授权和计费运行。
2. 公开响应中的每个分组标识都必须属于可见分组。
3. 公开响应中的每个模型都必须至少关联一个可见分组。
4. 前端不得通过客户端过滤承担保密责任；浏览器收到的数据已经完成服务端裁剪。
5. 目录投影不得反向写入 `model.GetPricing()`、能力缓存或 Relay 使用的分组映射。

## 方案比较

### 方案 A：全局可见分组白名单，服务端生成目录投影（采用）

系统设置保存“全部可见”或“指定可见分组”，`GET /api/pricing` 只返回目录投影。该方案与管理员的分组级控制意图一致，能阻止隐藏数据进入浏览器，也不会触碰调用权限。

### 方案 B：保存隐藏分组黑名单

操作直观，但即使管理员意图采用选择性公开，新建分组仍会默认公开，容易在尚未审查时泄露内部业务分组；同时难以清晰表达“只允许这些分组”。不采用。采用方案中的 `all` 模式则是管理员对当前及未来分组全部公开的明确选择。

### 方案 C：按模型维护可见性

粒度与需求不符。一个模型同时属于公开和隐藏分组时仍需处理分组价格，最终会形成两套互相冲突的控制面。不采用。

### 方案 D：公开接口返回全量数据，由前端隐藏

隐藏分组名称、关联和倍率仍可从网络响应中读取，不满足数据不下发要求。不采用。

### 方案 E：新增独立模型目录接口

会复制现有 `/api/pricing` 的模型、供应商、倍率和端点契约，并产生两份容易失步的缓存。继续扩展现有接口更符合当前架构。

## 设置语义

新增一个原子设置 `model_catalog_setting.group_visibility`，值为版本化 JSON 对象：

```json
{
  "version": 1,
  "mode": "all",
  "groups": []
}
```

支持两种模式：

- `mode: "all"`：所有当前及未来进入分组全集的分组都可见；`groups` 规范化为空数组。
- `mode: "selected"`：只有 `groups` 中列出的真实分组可见。空数组表示管理员明确关闭整个模型广场目录，接口仍成功返回空目录。

保存规则：

- 设置作为一个 JSON 文档一次校验、一次持久化、一次切换内存快照，避免模式和列表分两次保存造成中间状态。
- 分组标识使用后端真实标识精确匹配，区分大小写；不支持通配符、前缀或模型名。
- 保存时去除重复项并稳定排序；拒绝空标识、非字符串值和 `all`、`auto` 哨兵值。
- 新保存的未知分组标识视为输入错误并拒绝。分组后来被删除时，旧配置中的失效标识可保留在存储中，但不会进入公开投影；管理界面将其标记为“已不存在”，方便管理员清理。
- 切换到 `selected` 且不选择任何分组时，界面显示明确的空目录确认，但该状态是合法配置。
- 每次成功变更写一条紧凑管理员审计记录，包含操作者、旧模式、新模式、增加/移除数量和配置摘要；不为每个分组生成独立日志。

## 升级与迁移

- 已有站点没有该设置时解释为 `version: 1, mode: "all", groups: []`，因此升级前后公开目录保持一致。
- 新安装同样默认 `all`，无需预先枚举分组，也不会因新建分组而遗漏正常公开目录。
- 分组可见性控制本身只增加 Option 配置，不新增业务表，也不改写模型、渠道、能力或用户数据；配套 Sub2API 集成使用独立的候选发布记录，但该记录不保存可见分组白名单，也不改变此设置的迁移语义。
- 旧值为空字符串时按“设置不存在”处理；非空但格式错误的持久化值不得回退为全部可见。
- 在线保存失败时保留最后一份有效配置和目录快照。冷启动遇到非空非法配置时采用封闭失败：服务继续启动，公开定价接口返回空目录，并写一条系统错误和管理员告警，防止隐藏分组意外公开。

## 后端目录投影

### 构建顺序

1. 从现有 `model.GetPricing()` 取得原始定价快照，不修改其切片、映射或内部元素。
2. 从分组倍率配置及启用能力的显式分组构建分组全集，并取得分组说明。
3. 根据 `group_visibility` 计算可见分组集合。
4. 对每个原始模型计算它与可见分组的交集：
   - 普通 `enable_groups` 只保留可见项。
   - 包含 `all` 的模型在目录投影中展开为当前可见分组列表，不把 `all` 发送给浏览器，也不借此暗示隐藏分组关联。
   - 交集为空时移除整个模型。
5. 只保留存活模型使用到的供应商和端点展示元数据，避免产生孤立目录数据。
6. 生成稳定版本摘要并原子发布新的不可变目录快照。

模型同时属于公开分组和隐藏分组时，模型本身仍会出现，但 `enable_groups` 只包含公开分组。模型仅属于隐藏分组时，模型名称、元数据、供应商关联和价格均不会出现在公开响应中。

### Sub2API 发现模型

Sub2API `/v1/models` 同步结果首先是管理员可见的发现候选，不直接成为公开能力。候选模型只有同时满足以下条件才有资格进入原始定价快照及目录投影：

- 管理员确认导入并显式分配至少一个真实分组；
- 管理员为公开模型名配置明确的模型价格、模型倍率或受支持的分层计价规则；
- 对应渠道、能力和模型元数据均处于启用状态。

默认模型倍率或协议适配器的兜底值不算“显式定价”。缺少价格或分组的候选只出现在管理员同步差异中，不进入 `/api/pricing`。该约束只针对 Sub2API 发现候选，不追溯改变已有手工模型的兼容规则。

候选批准通过 `channel_model_publications(channel_id, public_model, approved, created_at, updated_at)` 持久化，不能仅从 `Channel.Models` 或运行时 Ability 反推。保存渠道模型只导入路由能力；管理员在差异确认中明确批准后才写发布记录。删除 Sub2API 渠道时清理对应记录。若同名模型已经由非 Sub2API 渠道提供，则继续沿用现有模型规则，不因新增一个未批准的 Sub2API 候选而被追溯隐藏。

## 公开接口契约

继续使用 `GET /api/pricing`。字段名称保持兼容，但所有带分组含义的字段都基于可见分组投影：

```json
{
  "success": true,
  "data": [
    {
      "model_name": "example-model",
      "enable_groups": ["default"],
      "quota_type": 0,
      "model_ratio": 1,
      "completion_ratio": 1
    }
  ],
  "group_ratio": { "default": 1 },
  "usable_group": { "default": "Default" },
  "all_group": { "default": "Default" },
  "auto_groups": [],
  "vendors": [],
  "supported_endpoint": {},
  "pricing_version": "effective-catalog-hash"
}
```

具体语义：

- `data`：只包含至少一个可见分组的模型；每项 `enable_groups` 已裁剪并展开，不包含隐藏标识或 `all`。
- `all_group`：只包含可见分组的标识和说明，是模型广场筛选项的唯一来源。
- `group_ratio`：只包含可见分组。登录用户继续应用其来源分组到目标分组的特殊倍率；匿名用户使用基础倍率。
- `usable_group`：当前用户真实可用分组与可见分组的交集。它只用于锁定标记，不扩大权限。
- `auto_groups`：只返回最终目标属于可见分组的自动分组展示项；不得借自动分组规则暴露隐藏标识。
- `vendors` 和 `supported_endpoint`：只返回存活模型引用的展示元数据，不包含渠道 ID、上游地址、密钥或管理配置。
- `pricing_version`：由原始定价版本和有效可见性配置共同生成；隐藏或恢复分组后必须变化。

即使已登录用户拥有某个隐藏分组，公开响应也不会返回该分组。反之，用户没有权限的公开分组会出现在 `all_group`，但不会出现在 `usable_group`，从而保持锁定展示。

## 缓存与并发

- 原始 `model.GetPricing()` 及其一分钟刷新策略继续服务现有定价和 Relay 数据，不在原对象上原地过滤。
- 新增不可变的全局目录基础快照，键由“原始定价版本 + 可见性配置版本”组成；快照包含已裁剪模型、基础分组倍率、分组说明、供应商和端点元数据。
- 每个请求只在基础快照上计算当前用户的特殊分组倍率、`usable_group` 和 `auto_groups` 交集，不进行逐模型数据库查询。
- 原始定价失效、分组/倍率更新、模型/能力更新、Sub2API 候选获批以及可见性设置更新都必须使目录快照失效。
- 设置保存先完成校验和候选快照构建，再原子切换设置与快照；并发请求只会看到完整旧版本或完整新版本。
- 对响应结构进行深复制或使用只读结构，禁止用户级倍率覆盖污染共享快照或其他用户响应。
- `/api/pricing` 的登录响应具有身份维度，不允许共享 HTTP 缓存跨用户复用。前端查询缓存键包含登录身份，登录、退出和切换账户时主动失效。

## 管理界面

Default 和 Classic 的系统设置均增加“模型广场分组可见性”区域：

- 使用分段控件选择“全部分组”或“指定分组”。
- 指定模式使用可搜索的复选列表展示完整管理分组全集，支持全选和清空。
- 每项展示分组说明和真实标识，不提供模型级复选框。
- 空选择、失效旧标识和保存冲突都有明确的就地状态；保存失败不得让界面伪装成功。
- 保存成功后重新读取配置和目录摘要，避免浏览器保留服务端未接受的状态。
- 移动端使用单列列表和固定底部保存区，分组长名称换行，不产生横向滚动、文字溢出或控件重叠。

设置读取和保存继续使用现有管理员鉴权与系统设置写权限。普通用户和未登录访客不能通过公开接口取得完整分组全集或可见性配置原文。

## 模型广场前端

Default 和 Classic 继续消费同一个 `/api/pricing` 契约：

- 分组筛选只从 `all_group` 构建，不从模型、`usable_group` 或本地常量补回隐藏分组。
- 每个模型只使用响应中的 `enable_groups` 计算卡片、表格、详情和最低价格。
- “全部分组”最低价只能在可见分组中选择；最低价来自锁定分组时继续显示锁图标和不可用提示。
- 具体公开分组即使锁定也保持可选择、可搜索，并展示对应价格。
- 可见性更新导致当前筛选项消失时，界面重置到“全部分组”，不能保留一个无数据的隐藏筛选键。
- 空目录展示正常空状态，不把管理员明确隐藏全部分组误报为网络错误。
- 桌面、窄屏和平板使用相同的数据和锁定语义。

Snow 当前是根页面的 vendored 视觉主题，控制台和 `/pricing` 仍由宿主前端提供。Snow 一致性要求是：启用 `HomePageMode=snow` 时不得引入独立目录数据源，进入模型广场后仍使用相同的服务端投影和当前控制台实现。若后续 Snow 自带模型广场，它必须先遵守本契约和锁定规则，不能从静态资产或其他接口恢复隐藏分组。

## 安全与隐私

- 隐藏在服务端完成。模型广场使用的 `/api/pricing` 响应及其派生页面状态均不应出现隐藏分组的结构化标识、说明、关联或倍率。
- 管理分组全集只通过管理员接口返回；设置写入沿用管理员鉴权、CSRF/会话保护和审计机制。
- 设置值不支持通配符，避免分组名称构造影响其他分组。
- 序列化响应前对所有分组承载字段执行同一套交集函数，避免只过滤 `data` 却从 `usable_group`、`auto_groups` 或倍率映射泄露。
- 目录过滤不参与 Relay 决策。安全测试必须证明隐藏分组中获授权用户仍能调用、未授权用户仍被拒绝。
- 模型描述和标签是管理员自由文本，本功能保证结构化分组字段不下发；管理员若主动把内部名称写入公开模型描述，该文本仍属于其公开内容管理责任。
- 错误信息和普通运行日志不输出完整隐藏分组配置。管理员审计详情可在受保护界面查看变更，但公开错误只返回通用消息和请求 ID。

## 错误处理

- 管理员提交非法 JSON、未知版本、未知模式、非法哨兵或未知分组时返回字段级错误，数据库和内存配置保持原样。
- 保存期间目录构建失败时整次更新失败，继续提供最后一份有效快照。
- 冷启动读取到非法非空配置时不使用“全部可见”兜底；返回成功的空目录并产生一次可操作的管理员告警。
- `selected` 引用的分组全部已删除时仍按空目录处理，不自动扩大到全部分组。
- 原始定价刷新暂时失败时继续使用现有最后有效定价/目录快照；没有任何有效快照时返回 `success: false` 的通用错误，不在错误中列出候选或隐藏分组。
- 可见分组集合合法但为空时返回 `200`、`success: true` 和空数组/空映射，这是管理员配置状态而非服务故障。

## 测试设计

### 后端单元与控制器测试

- 设置缺失和旧空值均迁移为 `all`，现有目录内容不变。
- `all` 模式自动纳入后来新增的真实分组。
- `selected` 模式只公开白名单，空白名单返回成功空目录。
- 非法 JSON、未知版本/模式、未知分组和哨兵值原子失败，旧快照不变。
- 冷启动非法非空配置产生空目录和单次告警，不泄露全量目录。
- 仅属于隐藏分组的模型完全消失。
- 同时属于可见和隐藏分组的模型保留，但序列化 JSON 不含隐藏标识、说明或倍率。
- `enable_groups: ["all"]` 展开为可见分组，不返回 `all`，也不包含隐藏分组。
- 登录用户有隐藏分组权限时，`usable_group`、`group_ratio` 和 `auto_groups` 仍不泄露它。
- 登录用户无公开分组权限时，公开分组仍出现且标为锁定所需的 `usable_group` 交集为空。
- 特殊分组倍率只对公开目标分组计算，公开价格与现有计费函数一致。
- 供应商和端点元数据只覆盖存活模型。
- Sub2API 候选在未定价、未分组或未确认任一状态下都不进入接口；全部满足后才按可见分组规则出现。
- 快照失效覆盖倍率、能力、模型状态、Sub2API 批准和可见性更新；并发和竞态测试证明共享快照不被用户覆盖污染。
- `pricing_version` 在有效公开目录变化时改变，在无效重复保存时保持稳定。

### 权限回归测试

- 隐藏一个分组前后，同一合法 Token 对该分组的 Relay 调用结果和扣费一致。
- 没有该分组权限的用户在隐藏前后都无法通过指定分组、模型映射或渠道回退绕过授权。
- 管理员可读取完整候选分组，普通用户及匿名请求只能读取目录投影。

### 前端测试

- Default 和 Classic 均以 `all_group` 为唯一筛选源，不从本地数据恢复隐藏项。
- 混合分组模型的卡片、表格、详情和最低价只使用可见组。
- 可见但不可用分组保持锁图标、可选择状态和价格提示。
- 当前筛选分组被隐藏后自动回到“全部分组”。
- 空目录、读取失败和保存失败呈现不同状态。

## 完成标准

- 管理员能够按整个分组全局控制模型广场展示，缺省状态为全部可见。
- 任何公开定价响应都不包含隐藏分组的结构化名称、说明、模型关联或价格。

- 公开但无权分组继续锁定可见，真实调用权限和计费没有变化。
- Sub2API 未定价或未分组候选保持隐藏。
- Default、Classic、Snow 宿主路径以及桌面/移动端行为一致。
- 全部验证在本地完成，生产服务器保持不变。
