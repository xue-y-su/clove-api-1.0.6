# Default 日期控件与模型广场可见性设计

## 状态与范围

- 日期：2026-08-19
- 状态：方案 B 已确认，等待实现计划
- 范围：`web/default` 主题及其现有模型广场可见性管理接口
- Classic 主题的日期组件保持现状
- 本次只改本地源码、测试和文档，不部署生产服务器

## 目标

1. 让 Default 主题所有面向用户的日期选择交互都使用项目内统一的 Calendar/Popover 样式，不再弹出浏览器原生日期或日期时间面板。
2. 将用户兑换码管理页的四个原生日期输入合并成两个明确的时间范围筛选：创建时间范围、过期时间范围。
3. 把模型广场分组可见性改成“模型分组 × 用户分组”的矩阵，让管理员能直接看懂每个模型分组对哪些用户分组可见。
4. 明确总开关语义：关闭时完全使用平台原有模型广场规则；开启时使用并保存自定义矩阵规则。关闭不会删除已保存的自定义规则。

## 方案

### 1. Default 日期控件

新增通用 `DateRangePicker`，基于现有 `Calendar`、`Popover`、`Button` 和 `react-day-picker` 的 `mode="range"`：

- 触发按钮显示本地化的起止日期；只有一端选择时显示已选端和占位提示。
- 弹层提供范围选择、清除、今天、近 7 天、本月四个预设。
- 桌面端显示双月日历，窄屏自动单月；弹层宽度有稳定上限，不产生横向溢出。
- 日期值在组件边界使用 `DateRange`，提交查询时仍转换为现有的当天起始/结束 Unix 秒，保持 API 契约不变。
- 所有按钮、标签、空状态和预设文案走 `useTranslation()`；中文、英文及现有语言回退到英文键。

升级现有 `DateTimePicker` 作为 Default 的唯一日期时间入口：

- 日期部分继续使用项目 Calendar。
- 时间部分使用样式化的小时/分钟输入，不使用 `datetime-local` 或浏览器原生日期弹层。
- 保留现有 `Date` 值和 `onChange` 契约，并支持最小/最大时间约束。
- 清除、键盘操作、语言切换和受控值同步必须保持可用。

按使用场景接入：

- `features/user-redemptions/index.tsx`：用两个 `DateRangePicker` 替代四个 `DateFilter`，将范围拆成 `createdFrom/createdTo` 与 `expiresFrom/expiresTo`。
- `features/usage-logs/components/compact-date-time-range-picker.tsx`：保留已有范围、预设和精确时间能力，但把两个 `datetime-local` 字段替换为统一的日期时间字段组件。
- `features/invitations/components/admin-invitation-dialogs.tsx`：用受控 `DateTimePicker` 替代 `datetime-local`，在表单提交前转换回现有本地日期时间字符串。

### 2. 模型广场分组可见性矩阵

管理页分为三个清晰区域：

1. **规则开关**：开关旁明确显示当前模式。
   - 关闭：`使用平台原有规则`，矩阵置灰且不可编辑，已保存自定义规则保留。
   - 开启：`使用自定义可见性规则`，矩阵可编辑。
2. **默认规则**：在自定义模式下选择“默认对所有用户分组可见”或“默认不对任何用户分组可见”，对应现有 `defaultMode`，用于没有单独规则的模型分组以及未来新增分组。
3. **可见性矩阵**：
   - 行是模型分组，展示分组说明和真实标识。
   - 列是用户分组，展示说明和真实标识。
   - 单元格勾选表示“该用户分组可以在模型广场看到该模型分组”；未勾选表示不可见。
   - 每行提供“全部用户分组（含未来）”动作、当前选中数量和“继承默认规则”动作。
   - 当行处于 `all` 模式时，当前用户分组单元格全部显示为已选，并用“含未来分组”标识区分；取消某个单元格会转换为明确的 `selected` 列表，而不是错误地清空整行。
   - 当行处于 `selected` 模式时，只保存勾选的真实用户分组；空列表明确显示“该模型分组对所有用户不可见”。
   - 无效的历史用户分组显示为“已不存在”，可清理但不会悄悄映射到其他分组。

矩阵在小屏上使用可横向滚动的表格容器，首列固定，单元格尺寸稳定；不使用嵌套卡片。保存按钮在页面底部保持可见，保存冲突重新读取服务端配置并提示管理员。

### 3. 状态与 API

继续使用现有原子接口 `GET/PUT /api/option/model-catalog-visibility` 及 `model-catalog-visibility-state.ts` 的版本化配置，不新增接口或数据库表。前端只负责把矩阵操作转换为现有：

```ts
{
  version: 3,
  enabled: boolean,
  default_mode: 'all' | 'hidden',
  rules: Record<string, { mode: 'all' | 'selected'; user_groups: string[] }>
}
```

关闭开关时仍保存 `enabled: false` 与当前规则；目录刷新后由现有 pricing 查询失效机制同步模型广场。权限、Relay 调用、计费和用户分组本身不受影响。

## 测试与验收

### 单元与组件测试

- 日期范围：空值、单端选择、完整范围、清除、今天/近 7 天/本月预设，以及结束日转换为当天 23:59:59。
- 日期时间：受控值同步、清除、时间修改、最小/最大值校验、语言切换，以及源码中不再出现 `type='date'`、`type='datetime-local'` 的 Default 业务控件。
- 可见性状态：关闭开关保留规则并恢复原规则提示；矩阵全选/取消单元格的 `all` 到 `selected` 转换；默认规则、空行、无效用户分组和保存请求序列化。
- 组件可访问性：每个矩阵单元格有可读标签，键盘可操作，移动布局不遮挡文本。

### 集成与浏览器验收

- `bun test ./src` 定向测试通过，再运行 Default 全量测试。
- `bun run typecheck`、涉及文件 lint、format check 和 production build 通过。
- Playwright 在桌面和窄屏分别验证：用户兑换码两个范围筛选、邀请有效期、审计时间范围、可见性开关、矩阵勾选/保存/刷新。
- 关闭自定义规则后，模型广场显示平台原有规则；开启并保存矩阵后，只显示对应用户分组可见的模型分组；刷新页面后状态一致。
- Classic 页面和后端 API 回归测试保持通过。
