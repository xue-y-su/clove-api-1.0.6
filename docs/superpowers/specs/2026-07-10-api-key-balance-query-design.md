# API Key 余额查询设计

## 目标

新增一个面向 API Key 持有者的公开余额查询页。访问者无需登录，只需提供 API Key，即可查看该 Key 当前还能消费的额度及直接影响使用的限制。

查询结果必须与真实 API 计费共用同一套规则，不能出现页面显示可用、实际请求却因订阅分组或计费偏好不匹配而失败的情况。页面只返回持有该 Key 即可合理获知的信息，不泄露用户名、用户 ID、邮箱、其他 Key、订单或完整订阅记录。

## 用户界面

### 页面入口

- 默认前端新增公共路由 `/token-balance`，无需登录。
- Classic 前端同样新增公共路由 `/token-balance`，无需登录，并使用相同的公共接口和响应类型。
- 页面使用原版 New API 默认前端现有的页头、主题变量、表单、按钮、边框、字号、间距和响应式组件，不引入独立视觉体系。
- API Key 仅保存在当前页面组件内存中；不写入 URL、日志、localStorage、sessionStorage 或查询历史。
- 查询完成后只显示遮罩后的 Key。

### 结果层级

结果页采用与钱包统计条一致的紧凑数据面板，不再使用居中的超大主金额或一张纵向过长的展示卡。按以下顺序展示：

1. 遮罩 Key、分组模式、分组名称和 Key 状态。
2. 三列核心指标。
3. 额度进度条及其直接说明。
4. 两列详情：额度构成和使用限制。

有限额 Key 的三列核心指标固定为“当前可用”“已使用”“不可用”。“不可用”只表示 Key 剩余额度中被当前资金来源限制的部分，不与“密钥剩余额度”重复展示。

无限额 Key 的三列核心指标固定为“当前可用”“已使用”“密钥限额”。第三列显示“无限制”，并明确说明“未设置独立额度上限”。“密钥无限制”与“账户或订阅资金无限”是不同概念，必须分开表达。

页面不展示用户名、账号标识、邮箱、其他 Key、订单号、购买来源或完整订阅列表。

### 进度条

有限额 Key 的进度条以 Key 总限额为总长度，顺序固定为：

1. 主题前景色：当前可用。
2. 灰色：已经使用。
3. 红色：受限额度。

计算关系：

- `Key 剩余额度 = max(Key 总限额 - Key 已使用, 0)`。
- `当前可用 = min(Key 剩余额度, 当前计费路径可累计消费额度)`。
- `受限额度 = max(Key 剩余额度 - 当前可用, 0)`。
- 三段之和必须等于 Key 总限额。

例如 Key 总限额为 `$150`、已使用 `$50`、当前计费路径只有 `$60` 可用，则显示主题前景色 `$60`、灰色 `$50`、红色 `$40`。红色区域直接说明限制原因，例如“受订阅额度限制”或“受账户余额限制”。

无限额 Key 不伪造固定上限。主数据直接使用当前计费路径的可累计消费额度，进度条以“当前可用 + Key 累计已使用”为当前快照范围，只显示主题前景色和灰色两段，不显示红色受限段，并明确标注“Key 未设置独立限额”。如果当前资金来源本身也是无限，则进度条完整显示为当前可用，不制造虚假的已用比例。

颜色不能单独承担语义。每个进度段同时提供文字标签和金额；红色区域同时显示具体限制原因。

### 原生视觉规则

- 页面继续使用 `PublicLayout` 和 New API 公共导航，不创建新的页面外壳。
- 正文继承应用的 `--font-body`，默认实际字体为 Public Sans；中文沿用应用现有 CJK 回退。实现中不额外下载或声明另一套字体。
- 页面标题沿用现有 `24px / 600 / 32px` 规格；按钮、标签、输入框和金额分别复用现有组件字号、字重及等宽数字栈。
- 使用现有 `Card`、`Input`、`Button`、`Badge`、`Alert` 和主题圆角变量，不在功能代码中硬编码一套独立圆角或颜色体系。
- 主色只使用主题 `foreground`/`primary`，不使用脱离主题的蓝色主金额。红色仅用于真实受限或不可用信息。
- 桌面端结果面板宽度与查询表单一致。移动端核心指标和两列详情改为单列，禁止横向滚动、文字重叠和金额截断。

### Classic 前端视觉规则

Classic 采用已确认的“Semi 标准查询面板”方案，不复制默认前端的 Shadcn 组件和黑白视觉：

- 继续使用 Classic `PageLayout`、固定公共顶栏和全局 `ClassicFrontendDeprecationBanner`。余额查询页不能隐藏“旧版前端即将停止维护”提示。
- 公共顶栏增加“余额查询”入口，位置与默认前端一致，并继续受 Classic 顶栏模块配置控制。
- 字体继承 Classic 当前实际字体栈：Lato、Helvetica Neue、Arial、Helvetica、Microsoft YaHei、sans-serif；不额外引入 Public Sans。
- 查询表单使用 Semi `Card`、`Form.Input`/`Input`、`Button` 和密码可见性按钮。输入与按钮遵循 Semi 默认 32px/40px 控件高度和约 6px 圆角。
- 结果使用一个标准 Semi `Card`：顶部为遮罩 Key、分组和状态 `Tag`；中部为三列指标；下方为 `Progress` 风格分段条和两列描述列表。
- Classic 的当前可用段使用 Semi 主题主色，默认是蓝色；已使用为灰色，受限额度为危险色。三段必须同时提供文字和金额，不能只依赖颜色。
- 有限额、无限额、查询失败和已识别但不可用的业务语义与默认前端完全一致，只允许组件与视觉表达不同。
- 查询错误使用 Semi `Banner` 或等价的页内错误提示，不使用只存在于 Toast 中的错误；限流和服务异常仍提供明确下一步。
- 移动端三列指标、两列详情和查询行改为单列；Classic 的顶栏、维护提示和页面内容不能互相覆盖。

### 计费模式展示

页面只展示真实参与当前计费路径的数据：

- `subscription_only`：不返回、不展示账户余额，不展示“可用订阅”栏目，也不展示订阅列表。主额度直接表示匹配订阅可提供的可消费额度。
- `wallet_only`：不返回、不展示订阅数据。
- `subscription_first`：只有在匹配订阅允许钱包回退时，账户余额才计入可累计消费额度；否则只计算匹配订阅。
- `wallet_first`：先计算账户余额，并将匹配订阅作为钱包不足后的可用来源。

“当前可用”表示这个 Key 后续可累计消费的额度。单次请求不能拆分到多个资金来源，因此“单次请求上限”作为独立限制展示，不能用累计额度代替。

### 生效限制

页面只列出能直接帮助持有者判断 Key 是否可用的限制：

- 计费来源：仅限订阅、仅限账户余额、订阅优先或账户余额优先。
- 单次请求上限：任一可选资金来源能够完整覆盖的最大额度，再受 Key 剩余额度限制。
- 分组限制：固定分组、用户默认分组或自动分组候选范围。
- 模型限制：无限制，或允许模型数量；允许展开查看模型名称。
- Key 有效期和当前状态。

不显示内部订阅 ID、逐条订阅扣费顺序或其他不影响使用判断的内部字段。

## 计费规则

### 共享订阅适用性

新增一个共享的订阅适用性规则层，供真实扣费和余额查询共同调用。输入至少包括用户、实际使用分组和订阅快照，输出该订阅是否能用于该分组。

规则如下：

- 订阅的 `upgrade_group` 非空时，仅适用于该分组及 `service.GetUserUsableGroups(upgrade_group)` 返回的授权子分组。
- `GetUserUsableGroups` 已包含全局可用分组、`GroupSpecialUsableGroup`、`+:child` 和 `-:child` 规则，不能在余额查询中复制一套简化实现。
- 历史订阅的 `upgrade_group` 为空时按旧行为兼容为不限制分组，避免升级后让已有订阅突然失效。
- 固定分组 Key 使用该固定分组判断。
- 空分组 Key 使用用户当前默认分组判断。
- `auto` Key 使用当前允许的自动分组候选范围。订阅只要适用于至少一个候选分组即可计入，但每份订阅最多计算一次；响应同时返回候选分组限制，避免把聚合额度误解为每个分组都可用。

### 活跃订阅

只有满足以下条件的订阅参与计算：

- 属于该 Key 对应用户。
- 状态为 `active`。
- `end_time` 晚于当前数据库时间。
- 分组适用性通过。
- 当前重置周期已经按现有订阅重置规则处理。

有限额订阅的剩余额度为 `max(amount_total - amount_used, 0)`；`amount_total = 0` 表示无限。多份匹配订阅按现有真实扣费顺序 `end_time asc, id asc` 尝试。

### 累计可用与单次上限

- 累计订阅额度是所有匹配订阅剩余额度之和，每份订阅只计算一次。
- 单次订阅上限是单份匹配订阅可完整覆盖的最大额度，不能把多份订阅拼起来支付一个请求。
- 累计账户额度是用户当前 `quota`。
- 单次账户上限是用户当前 `quota`。
- 有限额 Key 的累计可用和单次上限最终都不能超过 `remain_quota`。
- 任一参与来源为无限时，聚合计算使用显式 `unlimited` 标记，不用魔法数字代替。

### 四种偏好

- `subscription_only`：只计算匹配订阅；没有匹配订阅时可用额度为零。
- `wallet_only`：只计算账户余额。
- `wallet_first`：累计额度为账户余额加匹配订阅余额；真实请求先尝试由账户余额完整覆盖，余额不足时再尝试单份匹配订阅。
- `subscription_first`：先尝试匹配订阅。没有匹配订阅时使用账户余额；匹配订阅不足时，仅当这些匹配订阅允许钱包回退才加入并使用账户余额。

真实扣费中的“是否存在活跃订阅”和“是否允许钱包回退”必须改为只考虑当前请求分组匹配的订阅，不能继续检查用户所有活跃订阅。

## 后端结构

### 服务边界

新增一个不依赖 Gin 的余额快照服务，职责包括：

- 解析 Key 的有效分组范围。
- 读取并筛选匹配订阅。
- 根据计费偏好计算实际参与来源。
- 计算 Key 限额、累计可用、单次请求上限和受限原因。
- 生成只含最小必要字段的查询 DTO。

真实扣费通过同一订阅适用性函数筛选候选订阅。模型层继续负责事务、行锁、重置和预扣，服务层负责传入明确的实际使用分组。

### 公共接口

- 新增 `POST /api/token-balance`。
- 请求体仅包含 `key`，并受匿名请求体大小限制和严格 IP 限流保护。
- 该路由禁用响应缓存，并设置 `Cache-Control: no-store`。
- 不能把 Key 放在 URL 或错误信息中。
- 控制器解析并校验 Key，但不会把完整 Key 写入普通日志或错误日志。
- 返回统一的 `success`、`message` 和 `data` 结构。

最小响应字段：

- 遮罩 Key、Key 状态、是否无限额、总限额、已用和剩余。
- 当前可用、受限额度、受限原因、单次请求上限。
- 计费偏好和实际参与来源类型，不返回未参与来源的金额。
- 分组模式、固定分组或自动候选分组。
- 模型限制和有效期。
- 站点额度展示类型及换算所需的公共配置。

接口不返回用户信息、完整 Key、其他 Key、订阅 ID、订单、支付信息或账户完整资料。

### 状态与错误

- Key 不存在或格式无效：返回统一的“API Key 无效”，不区分不存在和格式错误。
- 用户被禁用、Key 被禁用、Key 已过期或 Key 已耗尽：返回可展示的不可用状态，不泄露用户资料。
- 数据库或缓存异常：返回通用查询失败信息，详细错误只进入脱敏后的服务端错误日志。
- 限流：返回现有结构化限流响应和 `Retry-After`。
- 所有金额计算使用站点现有 quota 整数单位，格式化仅在响应/前端展示层进行，避免浮点参与计费判断。

前端把状态分为两类：

1. 查询失败：空输入、无效 Key、请求过于频繁、服务或网络异常。页面不渲染结果面板，不回显原始 Key；使用原生页面内 `Alert` 提供可执行的下一步。
2. 查询成功但 Key 不可用：Key 已禁用、已过期、已耗尽或所属用户已禁用。页面继续渲染脱敏 Key 和准确状态，当前可用额度为零，并解释不可用原因，不能笼统显示为“查询失败”。

空输入由前端立即校验并把焦点留在输入框。无效 Key 使用统一提示以防枚举。限流优先读取 `Retry-After` 并展示可重试时间；服务异常不展示数据库错误、调用栈或内部服务名称。

## 前端结构

- 使用 TanStack Router 文件路由新增公共页面。
- 查询表单、结果面板、核心指标、进度条、详情区和错误状态拆成职责单一的小组件，但不为单页引入新的设计系统。
- 复用现有 `Button`、`Input`、`Card`、`Badge`、tooltip、主题变量、额度格式化方法和站点配置 hook。
- 使用现有 i18n 体系覆盖项目当前全部七种语言；本功能不得在任一支持语言中显示裸英文键。
- 桌面端保持紧凑信息层级；移动端改为单列，金额、标签和长模型名不能溢出或重叠。
- 查询中显示原版加载状态；错误使用页面内提示，不在 toast 中回显 Key。

Classic 前端使用 React Router 新增同路径公共页面，复用现有 `PageLayout`、Semi UI 和 Classic i18n。两个前端各自维护展示组件，但必须共享相同的字段语义、额度计算关系、状态映射和隐私规则，不允许在浏览器端各自推导一套计费算法。

## 数据库兼容

本功能不新增数据库字段或迁移。查询与筛选使用 GORM 表达式和现有索引，兼容 SQLite、MySQL 和 PostgreSQL。

订阅事务中的分组过滤不拼接原生数据库方言 SQL。候选订阅仍在事务内按现有顺序加锁，再通过共享规则筛选，保持三个数据库的行为一致。

## 测试与验收

### 单元测试

- 固定分组、默认分组和 `auto` 候选分组解析。
- `upgrade_group` 本组、授权子分组、移除子分组和空值兼容。
- 四种计费偏好的参与来源、累计额度和单次上限。
- 多订阅不能拼接覆盖单次请求，但累计额度可以求和。
- 有限 Key 的蓝、灰、红三段恒等于总限额。
- 无限 Key 不返回伪造限额。
- 未参与来源不会出现在 DTO 中。

### 后端集成测试

- 查询接口不需要登录，但必须提供有效 Key。
- Key 不出现在响应、错误、URL和测试日志中。
- 被禁用、过期、耗尽 Key 和被禁用用户返回正确状态。
- 严格限流和 `no-store` 响应头生效。
- 真实预扣与查询对同一订阅/分组给出一致结论。
- `subscription_first` 的钱包回退只受匹配订阅影响。
- SQLite、MySQL 和 PostgreSQL 的核心查询/预扣测试通过。

### 前端与浏览器测试

- 默认前端类型检查、单元测试和生产构建通过。
- Classic 前端 ESLint、Prettier 检查、i18n 检查和生产构建通过。
- 七种支持语言均无裸翻译键。
- 不在 URL、Web Storage 或控制台中留下 Key。
- 有限 Key、无限 Key、四种计费偏好和不可用状态均能正确渲染。
- 空输入、无效 Key、限流和服务异常使用准确且不泄密的页面内错误状态。
- 禁用、过期、耗尽和所属用户禁用仍显示脱敏结果，且当前可用为零。
- `subscription_only` 页面中不存在“可用订阅”栏目和账户余额字段。
- 桌面与移动视口无溢出、重叠、布局跳动或不协调配色。
- 页面视觉与原版 New API 的公共页保持一致。
- Classic 页面视觉与旧版 Semi Design 公共页保持一致，且全局维护提示仍可见、可关闭。

## 不在本轮范围

- 不向匿名查询者展示用户名、邮箱、用户 ID、订单或其他 Key。
- 不提供余额转移、充值、套餐购买或 Key 设置修改。
- 不把逐条订阅明细做成公开列表。
- 不改变套餐购买、退款或额度重置的业务规则。
- 不为余额查询单独发明一套计费近似逻辑。
- 不强行让 Classic 与默认前端像素一致；两者只共享业务语义，不共享视觉组件。
