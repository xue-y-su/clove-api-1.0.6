## 1. 目标

本轮修复全浏览器审计中仍成立的问题，并同步修正 Default、Classic 两套前端。实施按共享根因分批进行，不按页面堆叠局部补丁。最终结果必须同时满足后端业务不变量、中文错误契约、简洁使用日志、响应式布局和真实浏览器验收。

数据库代码继续同时兼容 SQLite、MySQL 5.7.8+ 和 PostgreSQL 9.6+。本地第三方支付完成页不作为验收条件，但金额、折扣、订单创建和失败反馈必须正确。

## 2. 已确认的产品决定

1. 关于页外部内容加载问题延后单独处理，本轮不改 `/about`。
2. 匿名首页能力数字当前已恢复正常，本轮只做回归检查，不修改展示方案。
3. `grok-imagine-image-lite` 已确认当前不可用，本轮不隐藏、不修上游，也不将其失败计入交付失败。
4. 游乐场聊天和图片模式均保留分组选择，并继续展示全部模型。切换分组不隐藏、不清空当前模型。
5. 分组只决定实际请求路由、订阅资格和计费；界面所选分组必须与请求使用分组完全一致。分组中没有当前模型路由时返回简洁中文提示，不展示渠道或分发器信息。
6. 联网搜索采用真实搜索与明确降级并存：明确支持原生联网时使用原生能力，否则在 Tavily 已配置时使用 Tavily；两者都不可用时禁用搜索选项并说明原因。
7. 订阅价格、购买确认和余额支付统一显示人民币符号 `¥`。
8. 安全与 IP 审计只把共享注册 IP、共享调用 IP、API `401` 和认证异常作为风险事实。两个账号共享同一有效公网 IP 即进入风险范围；普通上游 `4xx/5xx`、`429`、超时和内容拒绝不计入风险。
9. 普通用户只看简洁中文错误；渠道、数据库、内部实体、堆栈和上游诊断只进入去重后的服务端日志。
10. 使用日志保持简洁，不承担技术诊断，也不因普通页面浏览或筛选刷屏。
11. 管理员可管理全部用户兑换码，并在终止时选择退款或没收；用户允许领取自己创建的兑换码。
12. 自动生成的 API Key 保留 `sk-` 前缀，自定义 API Key 原样保存，不强制追加前缀。
13. Default 与 Classic 的视觉风格可不同，但业务行为、权限、错误和响应式可达性必须一致。

## 3. 总体方案

采用五个根因批次：

1. **数据与事务：** 注册随机码、API Key 生命周期、用户兑换码状态机和日志幂等。
2. **请求与能力：** 游乐场分组单一事实源、联网搜索能力判定和错误脱敏。
3. **安全审计：** 风险事实口径、聚合查询、按需详情和低噪声审计。
4. **前端交互：** 弹层、滚动、复制、弹窗生命周期和多设备布局。
5. **内容一致性：** 中文枚举、邮件模板、折扣、币种和移除失效入口。

每个批次先用失败测试固定可观察契约，再修改实现。共享后端契约先完成，两套前端随后消费同一事实源，最后进行多角色、多设备浏览器回归。

## 4. 数据与事务设计

### 4.1 注册随机归属码

用户提交的数据通过校验后，系统生成归属码并创建用户。若唯一索引报告归属码冲突，服务端仅针对该约束重新生成并有限重试；其他数据库错误不得被误判为冲突。达到重试上限时返回稳定业务错误，MySQL 索引名和原始错误只写服务端日志。单次提交只显示一次错误。

### 4.2 自定义 API Key 生命周期

自定义 Key 使用规范化后的完整秘密指纹判重。删除使用“保留审计记录、释放唯一秘密”的事务：删除时清除或替换不再可认证的秘密及唯一指纹，再标记业务记录删除，确保原值可由同一用户重新创建。实现不得依赖 MySQL 特有 SQL。

跨用户提交相同自定义 Key 时，在一个事务中锁定现有记录，将原记录标记为 `leaked` 并停止认证，同时拒绝新建。前端状态优先展示“已泄露”，不能仅显示“已禁用”。原持有者看到一次安全通知或使用日志摘要；提交碰撞者只看到“该自定义密钥不可用，请更换”，双方均看不到指纹和数据库原因。

自动生成 Key 继续使用 `sk-` 前缀；自定义 Key 不追加前缀。长度、字符集和重复校验都返回字段级中文原因。

### 4.3 用户兑换码

创建、领取、禁用、恢复、删除、终止、退款和没收都通过服务层状态机执行，事务内锁定兑换码、领取记录和相关余额。创建者可以领取本人创建的码。禁用、过期、耗尽、已终止和不存在分别返回稳定错误码和准确中文提示。

管理员对全部用户兑换码拥有查看和处置权限。终止时必须显式选择退款或没收并填写原因；结果、操作者、时间和请求 ID 进入管理员审计。操作成功后 API 返回最终对象或明确的删除结果，前端据此关闭弹窗并刷新，不保留空对象弹窗。

每次创建、领取或管理员处置只写一条用户可见的业务日志，例如“创建 ¥1.00 用户兑换码”或“领取 ¥1.00 用户兑换码”。内部余额前后值、实体 ID 和幂等键保留在服务端审计数据中，不进入普通使用日志正文。

## 5. 游乐场与联网搜索

### 5.1 分组单一事实源

聊天和图片表单都由同一个当前分组状态构造请求。分组控件更新后，请求、订阅资格、计费、日志和重试必须读取该最新值，不能读取模型选择时捕获的旧分组。重试保留原请求的模型与分组快照。

模型候选继续展示全部模型，切换分组不清空当前模型。若当前分组没有该模型的可用路由，服务端返回稳定的“当前分组没有此模型的可用路由”错误和一个请求 ID；前端不显示渠道名、渠道 ID、`distributor` 或上游原文。

### 5.2 联网搜索能力

原生联网必须同时满足显式模型规则和实际路由渠道能力，OpenAI 兼容协议本身不等于支持联网。未满足原生条件时，仅在 Tavily 已启用且 Key 已配置时调用服务端 Tavily 提供方。

公开选项接口只返回 `available`、可用路径和不可用原因，不返回 Tavily Key。前端在原生与 Tavily 都不可用时禁用 `basic/advanced` 选项并显示“管理员尚未配置联网搜索”；已经保存的旧搜索状态在加载时归一化为关闭。搜索失败只终止当前请求，页面保持可操作。

Tavily 调用继承请求取消，限制连接、响应和总超时，限制响应体、来源数量和注入上下文长度。来源 URL、标题和摘要先归一化再返回。用户错误保持简洁，服务端按请求 ID 记录提供方状态和耗时，不记录 API Key、查询全文或提示词。

### 5.3 移动端聊天

消息滚动区为固定输入工具栏预留真实底部空间。最新消息的菜单、复制、重试和编辑按钮始终位于工具栏上方；`390 x 844` 下交互边界不得与发送按钮相交。

## 6. 安全与 IP 审计

### 6.1 风险事实与排序

风险总览只包含以下事实：

- 同一有效公网注册 IP 关联至少两个账号；
- 同一有效公网 API IP 关联至少两个 Key 所属账号；
- API 返回 `401 Unauthorized`；
- 明确的登录失败、异常认证或账号安全事件。

普通上游失败不累计到“异常”或风险分数。列表按风险等级、风险事实数量和最近活动排序。基础设施地址、回环、私网、链路本地和无效地址不参与共享风险。

### 6.2 查询结构

列表接口只读取聚合事实并返回真实总数、分页和风险摘要；不为每行预加载全部账号与事件。点击“查看”后调用窄用途详情接口，分别分页读取账号归属、注册记录、API 调用、401、登录活动和安全时间线。任何“关联 300 个账号”都必须允许管理员继续翻页查看全部结果。

安全页面的时间范围、视图和页码进入 URL 搜索参数，选中状态必须明确，刷新和前进后退可恢复。普通切换、展开和读取不写使用日志；只有导出、敏感信息解密或权限变更等有安全意义的动作才写审计。

### 6.3 详情布局

桌面使用右侧抽屉或独立详情面板，手机使用全屏面板。详情脱离宽表格的横向滚动上下文，打开后立即看到风险原因、关联账号和时间线。时间线存在请求 ID 时可跳转到对应使用日志筛选。

IPv4 和 IPv6 使用可换行的等宽展示，不覆盖徽标和操作。有效公网 IP 后显示小型百度查询外链按钮；该按钮只打开外部查询页，不声称已接入 IP 画像 API。

## 7. 公告、邀请与系统内容

### 7.1 公告

系统公告从单一文本设置迁移为逐条公告列表。每条公告包含标题、HTML 内容、可选服务器图片、发布时间、发布状态和独立的“登录后弹窗”开关。编辑器不要求管理员选择内容格式，服务端统一清洗允许的 HTML。

图片由管理员上传到服务器公告媒体目录。启动时创建并验证目录可写，上传使用同目录临时文件和原子重命名；Docker 只调整该目录到运行用户。前端支持预览、删除和点击放大。

未登录用户不请求、不显示、不确认弹窗公告。公告确认与合规声明使用独立记录和接口。切换通知与时间线时保持面板状态，不闪空白。

### 7.2 邀请码与奖励状态

注册来源、邀请人奖励和被邀请人奖励分别使用中文业务枚举。筛选器必须明确筛选哪一维状态，不能用一组选项同时解释两段状态。被邀请人奖励继续自动发放；邀请人奖励只有提交提现并经管理员审批后入账。

### 7.3 系统内容

- 支付折扣显示“优惠 5%”或 `-5%`，不把 `OFF` 翻译成“关闭”。
- SMTP 内置模板、自定义模板默认名称、主题和正文完整中文化，占位符保持原样。
- 系统维护页移除“检查更新”按钮，只保留版本、作者和运行时间等只读信息。
- 订阅卡片、购买确认和管理员配置统一显示 `¥`，不改变 quota 存储和结算精度。
- 使用日志的状态码、事件键和前后值统一映射为中文业务语义，未知事件使用可理解的兜底文案，不直接显示内部键。

## 8. 两套前端交互契约

### 8.1 API Key 分组选择

桌面表格、平板和手机卡片都显示当前分组并可快捷切换。分组下拉通过各前端已有的 Portal/浮层能力渲染到顶层，根据可视空间自动向上或向下展开，设置最大高度并支持内部滚动。弹层不能被表格、卡片、对话框或页面的 `overflow` 裁剪，长分组名不得显示成不明的省略状态。

`768 x 1024` 下分组选择器与禁用、删除等操作的点击区域不得相交；必要时在该断点切换为卡片或操作菜单。状态标签为“已启用”“已禁用”“已泄露”等完整文本，其中泄露优先于禁用展示。

### 8.2 用户兑换码

桌面使用完整表格，手机使用连续可滚动卡片。页面只存在一个纵向滚动所有者，不使用固定高度配合 `overflow-y: hidden` 裁切业务内容。复制先使用 Clipboard API，权限或非安全上下文失败时使用项目共享回退，并始终保留可选中的只读完整代码。

管理员操作成功后关闭当前确认弹窗、清理目标状态、刷新列表并显示一次成功提示。刷新失败时保留完整目标和操作上下文供重试，不显示空白“管理”弹窗。

### 8.3 通用响应式规则

下拉、抽屉、弹窗、表格、卡片和固定工具栏在 `1440 x 900`、`1280 x 720`、`768 x 1024`、`390 x 844` 下均不得裁切、重叠或阻止滚动。长错误、IPv6、长用户名和长分组名允许换行或在有完整 tooltip 的前提下截断。焦点顺序、Esc 关闭和键盘选择保持可用。

## 9. 错误与日志契约

API 错误统一包含稳定错误码、HTTP 状态、面向用户的本地化消息和一个请求 ID。前端只展示一次请求 ID，不自行拼接内部 `message`、数据库错误或嵌套上游错误。

服务端日志记录请求 ID、业务错误码、内部原因、必要的模型/渠道/数据库上下文和耗时。相同请求中的同类错误只记录一次；周期性故障可按错误指纹限频，避免刷屏。日志不得包含完整 API Key、授权头、Cookie、密码、Tavily Key、兑换码、搜索查询全文或提示词。

使用日志只记录调用、登录、安全变更、Key 管理、兑换码、邀请审批、公告发布等有业务意义的动作。普通浏览、筛选和详情加载不写入使用日志。

## 11. 测试与验收

### 11.1 后端

- 注册归属码冲突自动重试和非冲突错误不误判。
- 自定义 Key 创建、跨用户碰撞、泄露状态、删除和同值重建。
- 用户兑换码自领、禁用、恢复、过期、耗尽、退款、没收和并发领取。
- 安全审计仅统计约定风险，两个账号共享即出现，详情总数和分页完整。
- 联网搜索原生、Tavily、未配置、超时、取消、空结果和畸形响应。
- 订阅分组不覆盖时返回准确稳定错误。
- 同一兑换业务动作只生成一条用户使用日志。
- 数据访问与迁移兼容 SQLite、MySQL 和 PostgreSQL；本地至少运行 SQLite 自动化与真实 MySQL 集成。

### 11.2 前端

Default 与 Classic 分别运行相关单元/组件测试、类型检查、lint 和生产构建。重点覆盖分组请求一致性、Key 下拉浮层、状态优先级、复制回退、弹窗关闭、公告逐条设置、中文枚举、订阅币种和移动端滚动。

### 11.3 真实浏览器

以匿名用户、普通用户和管理员三个角色，在桌面、窄屏笔记本、平板和手机四种视口逐项验收。除功能结果外，检查滚动、焦点、下拉方向、长文本、IPv6、空状态、加载状态、错误状态和浏览器前进后退。

Tavily、图片、SMTP 使用本地可控服务模拟成功、401、429、503、超时、取消和畸形响应。真实支付完成页在本地不要求成功，只验金额、折扣、订单和错误。测试期间持续检查系统盘和工作盘剩余空间，构建产物与浏览器证据优先写入 D 盘，结束后清理无用缓存。
