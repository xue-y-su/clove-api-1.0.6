# rc22 选择性融合、工具计费与渠道扩展设计

## 状态与范围

- 日期：2026-07-30
- 基线：Clove API `v1.0.1-beta`，当前源码以 New API `v1.0.0-rc.21` 为上游基线
- 上游参考：New API `v1.0.0-rc.22`，提交 `bc14c18f`
- 交付范围：本地源码、本地数据库兼容迁移、本地运行与自动化验收、Git 提交
- 明确排除：生产服务器部署、远端推送、GitHub Release、整包合并 rc22、Auth v2

本设计选择性融合 rc22 中与 Clove 现有架构兼容的修复，并完整加入工具附加计价、Sub2API、Alpha Search 和受控的上游异常响应预览。所有新费用必须进入 Clove 已有的统一计费会话，不建立第二条扣款链路。

## 背景与冲突

Clove 当前已经包含钱包不可变账本、订阅优先或钱包优先计费、签到奖励消费追踪、阶梯计价、用户兑换码和精简业务日志。rc22 的相关提交直接围绕官方额度字段结算，不能原样替换 Clove 的资金来源与流水逻辑。

已确认的冲突及裁决如下：

- rc22 工具价格页面声称按次模型不收工具费，但后端实际会合并工具附加费。Clove 统一为按次模型也收取实际工具费。
- Clove 当前以 Token 总数是否为零判断能否收费；Alpha Search 没有 Token usage，必须改为“存在可计费用量”判断。
- Clove 当前可能让工具费经过全部额外倍率；新设计提供可选模式，默认仅应用分组倍率。
- Clove 图片工具按质量和尺寸精确计价，rc22 使用统一每千次价格；两种模式均保留，默认精确计价。
- rc22 Debug 路径可能记录完整响应体；Clove 所有模式都必须脱敏、限长和限读取字节。
- rc22 大提交删除 Classic 并扁平化前端目录；Clove 保留 Default、Classic 以及由 Default 承载的 Snow 首页体验。
- Sub2API 模型发现不得绕过模型广场的分组可见性和定价管理。

## 非目标

- 不引入 Access JWT、Refresh Cookie、设备会话或 Auth v2 的三张新表。
- 不改变真实 API 分组权限、渠道授权、模型调用范围或订阅套餐语义。
- 不记录成功请求的原始上游响应体。
- 不为工具费创建独立消费日志、独立钱包账单或独立支付订单。
- 不自动把 Sub2API 发现的模型发布到模型广场。

## 总体架构

### 请求级 ToolBillingMeter

新增请求级工具计量器，封装以下职责：

- 冻结本次请求的价格、倍率、公开模型名和图片计价模式。
- 接收协议适配器上报的已确认工具事件。
- 按稳定调用标识去重，并在缺少标识时使用受限的协议级确定性键。
- 合并相同工具和单价的次数。
- 计算工具附加费、最低收费和结构化日志明细。
- 为流式请求提供“当前累计目标预留额度”。

协议适配器只上报事件，不读取系统设置、不计算价格，也不直接扣款。`BillingSession` 只接收总额度与明细，不理解工具名称或协议格式。

`ToolBillingMeter` 是工具计数和价格计算的唯一生产来源。现有 `calculateTextToolCallSurcharge`、`ComputeToolCallQuota` 以及 `image_generation_call`、`claude_web_search_requests` 等旧上下文附加费路径退出扣费链，避免新旧计算器叠加；只保留读取旧日志字段所需的兼容代码。

### 统一计费会话

总费用始终为：

```text
request_total_quota = model_quota + tool_quota
```

所有可能产生工具费的请求都创建 `BillingSession`，包括模型费为零、初始预扣为零和 trusted 请求。会话允许以零额度初始化；首次正额度 `ReserveToTarget` 必须退出 trusted 旁路并真实锁定资金，返回成功即表示相应资金已经预留。

`BillingSession` 继续负责预扣、追加预留、结算、退款、订阅与钱包溢出。新增原子 `ReserveToTarget`，在固定锁顺序下同时核对订阅与钱包并记录两侧累计预留，不能先提交一侧再尝试另一侧。资金顺序继续尊重 `subscription_only`、`wallet_only`、用户的 `subscription_first`/`wallet_first` 偏好以及套餐 `allow_wallet_overflow`；禁止溢出时不得暗中使用钱包。工具费跟随同一请求资金计划，订阅不足且允许溢出时只由钱包补足差额。底层不可变账本允许存在预扣、补扣和退差额分录，但所有分录使用同一请求 ID，用户页面、管理页面和业务审计聚合成一笔逻辑账单。

新增唯一终结入口 `FinalizeRelayBilling`。它接收模型用量、已提交的工具计量和交付状态，依次计算总额、结算资金、更新用户/渠道统计并写一条消费日志，任何步骤只执行一次并返回错误。非流式适配器先把“响应载荷 + usage”返回上层，只有终结成功才写客户端；结算失败不交付上游正文、不写成功消费日志，也不更新已用额度。

## 工具调用证据与去重

### 可计费证据

- OpenAI Responses 非流式：只遍历实际输出项，不按请求声明的工具计数。
- OpenAI Responses 流式：以完成事件中的 `item_id` 或 `call_id` 为主键，增量和终态事件复用同一记录。
- Claude Web Search：使用上游 `usage.server_tool_use.web_search_requests`。
- Gemini Google Search：只有响应确认发生 Grounding 搜索时计一次，不按请求声明推测。
- 图片生成：按实际成功产出的图片数量计费，失败或未完成图片不计费。
- 自定义函数：只有模型完整输出一个函数调用后计费，不等待客户端执行或回传结果。
- Alpha Search：上游返回 `2xx` 时固定确认一次 `web_search_preview`。

除 Alpha Search 的固定规则外，没有可靠响应证据时不收费。请求中仅声明工具、失败重试、未完成流式事件或未产出的图片均不构成费用。

### 自定义函数

自定义函数只有存在显式价格规则时才收费。未配置的函数免费。规则沿用：

```text
function_name
function_name:public_model_prefix*
```

函数名精确匹配，模型使用用户请求的公开模型名；最长模型前缀优先。渠道映射后的上游模型名不参与价格匹配。

## 价格快照与计算

### 请求快照

请求通过 Token、模型和分组校验后创建不可变快照，包含：

- 工具计费总开关。
- 完整的有效价格索引。
- 用户请求的公开模型名。
- 分组倍率和其他适用倍率。
- 倍率模式。
- 图片全局模式、模型前缀覆盖和精确价格矩阵。
- 当时的 `QuotaPerUnit`。

管理员在请求期间修改配置只影响后续请求。

### 普通工具公式

```text
tool_usd = sum(price_usd_per_1k * confirmed_count / 1000)
base_tool_quota = tool_usd * QuotaPerUnit * group_ratio
```

倍率模式：

- `group_only`：只应用分组倍率，默认值，与 rc22 的明确公式一致。
- `full`：在分组倍率后继续应用 Clove 的请求级乘法调整；工具调用不伪装成 Token，也不进入 Token 阶梯变量。

模型基础费用仍按现有普通、按次或阶梯计价计算，工具费在模型费用之后合并。按次模型同时收模型基础价和实际工具费。

分组倍率为 `0` 时工具费为 `0`，不触发最低收费。其他情况下，只要聚合后的工具费用为正但额度取整为零，整次工具费最低为 1 额度。所有工具先以高精度十进制求和，最后统一取整，避免逐项取整放大费用。明细 `subtotal_quota` 使用稳定名称/单价排序后的最大余数法分配整数额度，保证各明细之和严格等于 `tool_quota`；最低 1 额度确定性分配给排序后的第一个正价条目。

### 默认价格

价格单位固定为美元/1000 次：

- `web_search`：10
- `web_search_preview`：10
- `file_search`：2.5
- `google_search`：14
- `image_generation` 统一模式：150
- `web_search_preview:gpt-4o*`：25
- `web_search_preview:gpt-4.1*`：25
- `web_search_preview:gpt-4o-mini*`：25
- `web_search_preview:gpt-4.1-mini*`：25

配置值必须是有限非负数。`0` 仅关闭相应附加费，不禁止工具。运行时保存采用原子校验，任何非法项都拒绝整次更新。启动读取旧配置时逐项跳过非法值，保留有效项并使用内置默认兜底，同时生成一条管理员告警。

价格不设置业务硬上限。普通价格高于 `$10000/1000 次`，或图片矩阵单次价格高于 `$10` 时，界面显示高价警告并要求二次确认；该警告不改变后端对有限非负数的接受范围。

### 图片计价

支持两种模式：

- `matrix`：按质量和尺寸的单次美元价格精确计价，默认模式，初始值继承 Clove 现有矩阵。
- `flat`：使用 `image_generation` 的美元/1000 次价格。

管理员可编辑精确矩阵并恢复默认值。系统保存一个全局默认模式，并允许按公开模型前缀覆盖；最长前缀优先。实际费用按成功图片数量计算。

## 预留、结算与退款状态机

### 固定费用

Alpha Search 在发出首个上游尝试前按请求级只预留一次搜索费和模型基础费。单个渠道返回非 `2xx` 时只丢弃该 attempt，不把会话置为退款终态；全部渠道均失败时由最外层统一退款。收到首个 `2xx` 后，在向客户端发送状态码或正文前确认搜索事件并完成终结，因此客户端随后断开也保留该费用。

### 非流式请求

非流式响应先在内存中完成受限解析，收集实际工具用量，计算最终总额并完成结算，然后才写给客户端。余额不足时不交付响应，并以规范化额度错误结束请求。

### 流式请求

流式处理在确认新的收费工具事件后：

1. 计算当前累计目标预留。
2. 调用 `BillingSession.Reserve` 追加预留。
3. 预留成功后才向客户端转发对应工具完成事件。
4. 预留失败时立即取消上游 Context、关闭响应体并终止后续输出。

请求结束按实际总额结算并释放多余预留。客户端断开时，已完成工具调用和已产生模型用量照常结算，只退回尚未发生的预留。

### 重试

每个渠道尝试使用独立的暂存计量器，通过 `NewAttempt`、`CommitAttempt`、`DiscardAttempt` 管理；只有最终成功并交付的尝试提交费用。失败 attempt 不产生工具费用，请求级预留保留给后续尝试，全部尝试失败才统一退款。由平台承担失败上游成本。已开始向客户端输出的流不能切换到另一渠道重放。

客户端断连时，以已经转发的本地模型 usage 和已确认工具事件执行一次部分终结，只退未发生的预留。缺少稳定 ID 的流事件优先使用协议输出索引；仍无索引时使用规范化完成载荷摘要，并对相同匿名完成事件保守去重。

### 并发与幂等

- 钱包和订阅调整继续使用现有事务锁和稳定请求 ID。
- 相同工具完成事件重复到达不增加计数。
- `Reserve`、`Settle` 和 `Refund` 保持幂等状态机。
- 订阅耗尽后钱包补扣仍属于同一逻辑账单。
- 用量统计、用户已用额度和渠道已用额度只写最终总额一次。

## 消费日志与账单展示

现有消费日志的 `quota` 保存模型费与工具费合计。结构化 `other` 增加：

```json
{
  "billing_breakdown": {
    "model_quota": 0,
    "tool_quota": 0,
    "total_quota": 0
  },
  "tool_surcharges": [
    {
      "name": "web_search_preview",
      "count": 1,
      "unit": "usd_per_1k_calls",
      "unit_price": 10,
      "subtotal_quota": 5000
    }
  ]
}
```

列表仍只显示请求总消费。用户查看自己的日志、管理员查看全站日志时，可在详情中看到一行紧凑明细。免费、未配置或未确认的工具不生成附加费条目。不得为同一请求新增第二条消费日志、第二条钱包账单或逐工具业务审计。

钱包流水的用户与管理员查询层按 `reference_type=relay_request + reference_id` 先聚合再分页，不能先逐行分页后在当前页合并。聚合项保留底层分录数量和可展开明细，列表总额与不可变分录之和一致。

配置变更每次保存只写一条紧凑管理员审计，记录操作者、配置类别和变更项数量，详细差异按需展开。

## Alpha Search

### 接口

新增：

```http
POST /v1/alpha/search
```

接口复用现有 API Token、模型访问、分组、渠道选择、模型映射、参数覆盖、限流和计费中间件。请求体保留未知字段；仅在模型发生映射时以结构化 JSON 修改 `model` 字段。

支持渠道类型：

- Sub2API
- Codex
- Advanced Custom

路由选到不支持的渠道时返回可重试的内部不匹配结果，继续寻找下一条支持渠道，不产生重复用户错误日志。全局开关默认开启；关闭时入口在进入渠道路由和计费前返回明确的功能关闭错误。

上游通常不返回 usage。上游 `2xx` 被定义为一次已完成搜索，固定计入 `web_search_preview`；Token 定价模型只收工具费，按次模型收模型基础价加工具费。

### 管理员测试

渠道管理为三类支持渠道增加 Alpha Search 测试操作。管理员输入查询与模型后执行真实受限请求，展示状态、耗时和脱敏结果摘要，不计入普通用户钱包或用量统计。

首期不新增用户搜索页面，也不接入 Playground。

## Sub2API 渠道

### 渠道定义

新增稳定渠道类型 `ChannelTypeSub2API = 59`，不改变任何已有渠道编号。渠道根据请求入口的最终 `RelayFormat` 自动委派给 OpenAI、Claude 或 Gemini 适配器，并保留 Clove 现有代理、超时、SSRF、状态码映射、参数覆盖和自定义请求头能力。

认证头规则：

- 始终发送 `Authorization: Bearer <key>`。
- Claude 原生格式同时发送 `x-api-key` 和必要的 `anthropic-version`。
- Gemini 原生格式同时发送 `x-goog-api-key`。

首期与 rc22 保持一致，支持聊天、Responses、Embedding、OpenAI 图片、Claude 原生、Gemini 原生和 Alpha Search；明确不承诺 Sub2API 音频与 Rerank 转发。

### 模型发现

管理员点击“获取模型”后请求上游 `/v1/models`。模型响应使用独立超时和 8MiB 字节上限，解析失败、超时或非 `2xx` 不修改渠道。

成功后展示差异：

- 上游新增。
- 当前仍存在。
- 上游已缺失。

管理员确认后才更新现有渠道模型字段。缺失模型默认保留，只有显式勾选才移除。发现过程不创建模型价格、不设置公开分组、不改变模型广场；未定价或未归入可见分组的模型保持不公开。

导入路由能力与发布模型广场是两个独立动作。新增非账务持久记录 `channel_model_publications(channel_id, public_model, approved, created_at, updated_at)` 保存 Sub2API 候选是否经管理员确认发布。仅由 Sub2API 引入的模型必须同时满足：发布记录为已确认、价格配置中存在该公开模型的显式条目、并至少属于一个非 `all/auto` 的真实启用分组，才有资格进入模型广场原始目录。已有其他渠道能力的同名模型不受该门槛追溯影响；删除渠道时同步清理其发布记录。

## 上游异常响应诊断

### 记录边界

只处理上游非 `2xx` 响应。默认模式 `fallback_only` 仅在系统无法提取有效错误消息时记录预览，包括非法 JSON、HTML 错误页和空消息 JSON。可切换 `all_errors`，为所有非 `2xx` 响应记录预览。

成功响应永不进入该功能。响应预览不返回给 API 调用用户，用户只获得规范化错误与请求 ID。

### 有界读取与预览

- 错误诊断最多读取 64KiB；超过部分丢弃并标记截断。
- 预览默认 2048 个字符，可配置 256 至 8192。
- Debug 模式也执行相同字节上限、脱敏和字符截断。
- 记录原始字节长度或“至少达到上限”、截断标识和 SHA-256 摘要。

脱敏同时使用结构化键过滤和文本模式：Authorization、Cookie、Set-Cookie、API Key、Bearer、JWT、常见密钥格式，以及可能回显用户请求的 `prompt`、`input`、`messages`、`request_body` 等字段。保留用于诊断的状态码、错误类型和规范化错误消息。

### 去重与存储

以“渠道 ID + 状态码 + 响应摘要”为键去重。默认 60 秒内仅记录首条完整预览，窗口结束补一条服务端日志级累计次数摘要；窗口可配置为 0 至 3600 秒，0 表示关闭去重。累计摘要绝不新增用量日志、钱包流水或计费动作。去重状态只保存在进程内存并有容量上限，不新增持久表。

默认只写服务端错误日志。管理员可开启同步到现有失败用量日志详情；同步内容已经脱敏，跟随现有用量日志保留和清理策略，不另建日志行。

错误处理拆为纯解析器和唯一 `DiagnosticSink`。解析器一次性有界读取响应，返回规范化错误与已脱敏诊断对象，本身不写日志；Sink 负责首条服务端预览和重复摘要，并在启用同步时把诊断附加到当前既有失败用量日志的 `other`。诊断对象不得进入可能返回客户端的 `NewAPIError.Metadata`，现有 `showBodyWhenFail` 完整正文路径被移除。

全局诊断开关默认开启。关闭后仍记录状态码、渠道 ID、请求 ID 和错误类别，不保存响应预览。

## 系统设置

扩展现有分层配置：

## rc22 配套修复

除上述功能外，选择性融合以下已批准修复，不整体 cherry-pick 大提交：

- Responses 流式工具调用按 `item_id/call_id` 复用，避免终态重复下发和重复计费。
- 创建或改名为同名模型时保护已有价格配置。
- 异步任务使用 CAS 完成终态与退款，退款后清零并持久化任务 quota；不恢复已被官方撤回的自动对账扫描器。
- 硬删除用户时清理 Token、OAuth、2FA、备用码和 Passkey，同时保留 Clove 自定义审计与钱包数据完整性规则。
- Realtime GA 模型不再发送 beta header，仅 preview 模型保留。
- 修复 `auto` 分组模型展开。
- 同步 Codex 和高级自定义渠道的模型发现能力。
- 用户列表使用服务端排序，并回移不依赖 rc22 前端重构的搜索防抖、充值输入清空和大余额展示修复。
- 代理 URL、缓存键和连接失效修复以 Clove 现有 TLS、超时和 SSRF 加固为基础手工融合。

## 数据兼容与升级

- 新配置通过现有 Option/分层配置保存，不新增账务表；只为 Sub2API 模型发布批准新增独立的非账务持久记录。
- `ChannelTypeSub2API = 59` 只扩展枚举和映射，不改已有渠道记录。
- 现有工具价格配置原样保留；缺少的新内置项使用代码兜底。
- 新安装和已有站点升级后，工具计费、Alpha Search 和异常诊断总开关均默认开启。
- 旧消费日志没有 `tool_surcharges` 时按纯模型费用展示。
- 账本聚合使用现有 `reference_type=relay_request` 与请求 ID，不修改历史分录。
- 本次不创建 Auth v2 表，不要求现有用户重新登录。

## 错误处理

- 工具价格运行时保存失败时保留旧快照，不部分应用。
- 追加预留失败立即取消上游，不能让余额变负，也不能静默免单。
- 结算资金成功但 Token 限额更新失败时沿用现有补偿和告警策略，不重复退款资金。
- Sub2API 模型获取失败不修改已有模型列表。
- Alpha Search 非 `2xx` 不收费并进入正常渠道错误处理；`2xx` 后客户端断开保留一次搜索费。
- 日志诊断失败不得覆盖原始上游错误，也不得影响退款或重试。
- 响应预览、工具明细序列化或审计写入失败不得触发第二次消费。
