# Clove API 展示版本设计

## 目标

所有页面和 API 可见版本统一显示为：

`v1.0.0-rc.21-Clove API`

机器使用的版本标识继续保持合法格式，不把带空格的展示文本用于 Docker
镜像标签、Electron SemVer、依赖解析或发布产物命名。

## 设计

1. 在后端定义统一的展示版本，页面和 API 不再直接展示机器版本。
2. `/api/status` 的 `version`、版本响应头及其他面向调用方的版本字段使用
   展示版本。
3. 系统维护页继续读取状态接口，因此“当前版本”自动显示统一的展示版本。
4. 数据库实例版本、构建元数据、Docker 标签和 Electron 包版本继续使用
   `VERSION` 中的机器版本。
5. 前端已有直接读取构建版本的可见位置改为使用后端展示版本；仅用于缓存失效
   或调试元数据的位置保留机器版本。

## 兼容性

- 展示版本允许包含空格。
- 机器版本保持现有合法格式，部署和打包命令无需接受带空格的标签。
- 不新增管理员设置项，避免展示名称在不同节点产生漂移。
- 不改变 API 字段结构，只调整可见版本字段的值。

## 测试

1. 后端测试验证状态接口和版本响应头返回
   `v1.0.0-rc.21-Clove API`。
2. 前端测试验证系统维护页使用接口返回的展示版本。
3. 源码检查验证页面和 API 路径不再暴露
   `v1.0.0-rc.21.clove-enhanced`。
4. Docker、Electron 和 Compose 测试验证机器版本仍为合法标识。

## 验收

- 系统维护“当前版本”显示 `v1.0.0-rc.21-Clove API`。
- 其他页面和 API 可见版本保持一致。
- Docker 镜像、Electron 打包和现有部署配置不因空格失效。
