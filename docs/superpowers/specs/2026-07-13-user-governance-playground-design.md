# 用户治理、钱包与游乐场能力设计

**日期：** 2026-07-13

**状态：** 已确认，待实施计划
**范围：** 用户权限与资料、IP 审计、Token 余额与自定义 Key、用户兑换码、邮件模板、日志体验、游乐场联网/思考/生图

## 目标

在不替换 New API / QuantumNous 品牌和模块路径的前提下，完成以下能力：

1. 保留现有 Root 管理模型，并补齐用户资料与管理操作审计。
2. 规范个人资料、昵称、用户名、头像与封禁反馈。
3. 让余额查询页以钱包可消费额度为唯一主余额，订阅额度独立展示。
4. 提供用户自定义 CloveAPI Token，并在碰撞时处置疑似泄露凭据。
5. 支持用户从钱包创建公开兑换码和拼手气红包。
6. 提供多模板验证码邮件、预览和测试发送。
7. 统一绘图/任务/合规/来源归属记录的表格、真实总计和分页体验。
8. 提供分层 IP 审计与可追溯的业务审计事件。
9. 在游乐场提供原生联网优先、Tavily 降级、思考强度和独立生图模式。

## 非目标

- 不创建永久图片图库，不持久化游乐场生成图片二进制或会话历史。
- 平台搜索第一版只接入 Tavily；保留抽象但不实现其他供应商。
- 不将联网搜索作为游乐场顶层模式。
- 不将订阅剩余额度合并进钱包资产。
- 不将 Tavily、SMTP、上游凭据、完整 Token、Cookie 或 Authorization 头返回给浏览器或写入业务审计。
- 头像不由 CloveAPI 接收、转发或存储，旧图不由 CloveAPI 删除。

## 1. 用户权限层级与封禁

### 1.1 角色与能力

系统保留普通用户、管理员和 Root 三种角色，不增加额外的 Root 子层级或用户标记。

| 操作 | 管理员 | Root |
| --- | --- | --- |
| 管理普通用户 | 是 | 是 |
| 提升普通用户为管理员 | 否 | 是 |
| 管理管理员 | 否 | 是 |
| 提升用户为 Root | 否 | 仅 ID=1 |
| 降级其他 Root | 否 | 仅 ID=1 |
| 禁用或删除 Root | 否 | 否 |

- ID=1 通过既有专用动作提升或降级其他 Root，且不能降级自己。
- 其他 Root 只能管理普通用户与管理员，不能执行 Root 角色变更。
- 角色和封禁状态变化后，立即失效用户、Token、授权策略缓存。
- 前端仅镜像权限规则用于 UX；服务端必须集中强制校验。

### 1.2 用户封禁理由

封禁用户时管理员可填写两个可选字段：

- **用户可见理由**：被封用户登录或访问受保护接口时显示。
- **内部处理备注**：仅管理端与审计可见，绝不返回给该用户。

行为：

- 有用户可见理由时提示：`账号已被封禁：<理由>`。
- 未填写时提示：`账号已被封禁，请联系管理员。`。
- 解封后不再向用户显示封禁理由，历史理由保留在审计日志。
- 封禁或解封立即失效会话、Token 与缓存。
- 封禁、解封均按角色层级校验，并记录操作者、目标、理由/备注、时间、来源 IP、请求 ID 与结果。

## 2. 个人资料、用户名、昵称与头像

### 2.1 用户名和显示名称

- `display_name` 为用户昵称；新账户创建时默认等于用户名。
- 普通用户不能修改用户名，仅可修改显示名称和头像。
- 显示名称首次设置可立即保存；之后受系统设置中的昵称冷却期约束，默认 7 天。
- 冷却期、最大长度和其他显示名称策略由系统设置配置；服务端始终强制。
- 昵称允许可见 Unicode，包括中文、英文、数字、emoji 和常用符号；拒绝控制字符、HTML 标签、危险双向文本控制符与空白滥用。
- 管理员及以上可修改自己的用户名。
- 管理员及以上可在用户管理中修改其权限范围内目标用户的用户名：管理员可改普通用户，Root 可改普通用户和管理员。
- 用户名修改必须做唯一性、格式和角色层级校验，失效用户缓存并写审计。
- 若显示名称仍等于旧用户名，管理员修改用户名时可同步显示名称为新用户名；已经自定义的显示名称不自动覆盖。

### 2.2 资料头部

资料头部统一为两行：

```text
[头像]  显示名称
        @用户名 • 已绑定邮箱 • 角色 • 邀请人邀请码
```

- 用户名始终带 `@`。
- 邮箱仅在已绑定时显示；不存在时整项隐藏，不产生空分隔符。
- 角色显示有效身份：`User`、`Admin`、`Root`。
- 最后一项是邀请人的邀请码，仅在用户由邀请关系注册且该邀请码存在时显示。
- 用户 ID、用户组和邀请人其他信息不放入副标题，保留在资料详情或管理员用户查看中。
- 所有存在字段使用 ` • ` 作为唯一分隔符，不混用 `/` 或其他符号。

### 2.3 第三方图床头像

- 用户在个人资料直接选择头像，浏览器直传 `https://img.scdn.io/api/v1.php`；无需填写图床 URL 或 API Key。
- CloveAPI 不接收、转发或下载图片数据，因此不进行服务器侧文件大小、像素或格式检查。
- 前端拒绝视频作为头像；允许图片/动图：JPEG、PNG、WebP、GIF、动态 WebP。
- 图床上传成功后，前端提交图床返回 URL 以保存头像；后端仅接受系统设置中允许的 `img.scdn.io` 域名 URL，拒绝任意外链、本地路径、内网地址与未受信任域名。
- 更换头像后立即刷新资料展示；旧头像只解除引用，不尝试删除第三方图床文件。
- 图床上传或跨域失败、返回非允许图像地址时不更新头像并给出明确提示。
- 系统设置提供第三方头像图床启用开关、上传端点和允许域名；不下发长期图床密钥。

## 3. Token 余额与自定义 API Key

### 3.1 余额口径

公共 Token 余额查询的主指标为**钱包当前可消费额度**：

- 不将活跃订阅剩余额度加入钱包主余额。
- `token_callable_quota` 独立表示 Token 状态、限额与用户状态生效后的可调用额度。
- 订阅仅以辅助模块展示计划、状态、总额、已用、剩余。
- 后端返回明确分项快照，前端不得自行混算钱包、订阅和 Token 限额。

### 3.2 用户自定义 Token

自定义 API Key 是用户为**自己的 CloveAPI Token**指定完整访问字符串，不是上游供应商凭据。

- 仅当前认证用户在新建自己的 Token 时可填写；管理员和 Root 不可代替其他用户指定或修改 Token 字符串。
- 创建后 Token 字符串不可编辑，只能禁用/删除后重新创建。
- 无 `sk-` 前缀要求；长度 16–128；仅允许 ASCII 字母、数字、`_`、`-`。
- 自定义 Token 沿用既有分组、模型限制、钱包计费、订阅、IP 限制、过期、额度与审计。
- 完整值仅在创建成功时显示一次；后续列表、日志、审计、错误、缓存键和指标只使用脱敏标识、Token ID 或不可逆派生值。
- 认证必须完整精确匹配 Key。兼容层可移除一次 `sk-` 前缀后再次完整匹配，但不得按 `-` 截断 Key。

### 3.3 碰撞即疑似泄露

当用户提交的自定义 Key 与任何现有有效 Token 完整精确匹配时：

1. 碰撞请求只返回统一消息：`自定义 API Key 不可用，请更换后重试。`，不得泄露碰撞对象；长度和字符格式错误必须分别说明 16–128 字符范围及允许字符，便于用户直接修正输入。
2. 原 Token 在受控事务/幂等流程中标记为疑似泄露并系统禁用。
3. 原 Token 不可手动重新启用，所有者需创建和替换新 Token。
4. 写入 `custom_key_collision_suspected_compromise` 审计事件，仅记录 Token ID、脱敏标识、操作者/来源、时间和结果。
5. 向原 Token 所有者发送泄露提醒邮件。
6. Token 管理页显示：`此 API Key 因疑似泄露已被系统禁用，请创建并替换新的 Key。`
7. 同一 Token 后续重复碰撞不得重复发邮件或重复写同类审计。

数据库唯一约束是并发创建的最终保障。创建失败按用户/IP 限速，且完整 Token 不得进入 Redis key、日志或指标标签。

## 4. 用户兑换码与钱包

### 4.1 兑换码类型和资金规则

普通用户可在钱包中从**可用钱包余额**创建兑换码；不消耗订阅额度。只提供两种模式：

1. **一次性公开兑换码**：创建时预扣固定额度，任一用户领取后结束。
2. **拼手气红包兑换码**：创建者设置总额度和领取人数；每个用户最多领取一次，系统按当前对外显示单位与统一舍入规则随机分配，最后一人领取余量。

- 创建时立即预扣钱包额度；金额输入、扣减、随机分配、领取入账和退款统一使用当前展示单位和 `common.QuotaRound` / `common.QuotaFromFloat` 等统一转换，不使用裸浮点转 `int`。
- 必须设置有效期，不允许永不过期，最长 30 天。
- 过期或创建者手动取消时，未领取余额自动退回创建者钱包。
- 已有人领取后仍允许取消；已领取部分不回滚，只退回未领取余额。
- 创建、领取、取消、自动过期退款必须使用事务、状态条件更新与幂等保护，防止重复领取和重复退款。
- 创建、领取、取消、过期、退款均写用户账本和业务审计。

### 4.2 用户入口：我的兑换码

- 钱包仅提供创建兑换码和兑换兑换码。
- 个人侧栏新增**我的兑换码**，仅展示当前用户创建的兑换码。
- 用户可查看完整兑换字符串、模式、总额、已领/剩余、领取份数、有效期、状态、退款状态和详情。
- 用户可复制、查看详情、取消自己的有效兑换码；不可查看其他用户创建的兑换码。

### 4.3 管理入口：用户兑换码

- 管理员设置的兑换码区域新增**用户兑换码**选项，仅管理员及以上可见。
- 提供按创建者、状态、模式、时间、到期和退款状态的检索与详情。
- Root 可查看完整领取明细并执行禁用/取消等管理动作；管理员可见和可操作范围遵循其用户管理权限。
- 所有敏感读取、查看详情、禁用、取消、退款均写读取/管理审计。

## 5. 验证码邮件模板中心

系统包含不可删除的默认模板和多个自定义模板。

- 模板字段：ID、显示名称、主题、HTML 正文、默认标记、启用标记、排序、创建/更新时间。
- 仅允许变量：`{{code}}`、`{{site_name}}`、`{{expiration_minutes}}`。
- 没有有效自定义启用模板、模板被删除或内容被清空时自动回退默认模板；设置页始终可显示默认模板。
- 默认模板不可删除，可复制为自定义模板；自定义模板可新建、复制、编辑、删除、排序、启用。
- 保存时校验主题/正文长度、允许变量、未知变量和基础 HTML 结构；模板/SMTP 相关更新使用原子批量提交。
- 提供模拟数据实时预览和向指定地址测试发送；测试发送有速率限制、超时与脱敏错误。

## 6. 日志体验与业务审计

### 6.1 四类记录统一数据表

以下四个选项统一采用使用日志页的数据表体验：

1. 绘图日志；
2. 任务日志；
3. 合规确认记录；
4. 来源归属确认记录。

每个选项支持：类别筛选、日期范围、管理员范围切换、列显隐、桌面表格、移动端卡片、服务端分页、页码跳转、前后翻页和每页行数选择。URL 保留当前类别、筛选、日期、页码和每页行数。

底部 `总计：N` 必须由后端按当前完整筛选条件执行真实 `COUNT(*)` 返回：不使用当前页长度、不做 10,000 截断。任务查询发生数据库错误时必须返回明确错误，不得伪装为空列表或显示 `总计：0`。

### 6.2 业务审计边界

业务审计按业务动作写入，而不是按每次页面访问写入。

必须记录：

- 注册、登录成功/失败、退出；
- 资料变更、密码/2FA/Passkey/邮箱等安全设置变更；
- Token 创建、更新、禁用、删除、自定义 Key 泄露处置、认证/IP 限制拒绝；
- 充值、扣费、退款、余额转移；
- 兑换码创建、领取、取消、过期退款和管理员管理；
- 角色、Root、封禁/解封、用户管理变更；
- 系统设置、渠道、模型配置变更；
- 管理员查看用户安全详情、IP 审计、敏感查询/导出；
- 游乐场联网搜索路径/失败、生图请求和结果状态、关键任务操作；
- 后台自动退款、订阅重置、配置重载、外部依赖失败与恢复。

不写入业务审计库：纯页面访问、静态资源、无业务意义页面刷新、健康检查和监控探针。

每条审计含事件类型、操作者、目标对象、时间、来源 IP、请求 ID、结果与必要脱敏上下文；不得写入密码、完整 Token、Cookie、Authorization、Tavily Key、SMTP 凭证或敏感原始请求体。

## 7. 用户安全详情与 IP 审计

### 7.1 IP 数据和详情

补齐普通注册 IP 记录，并提供：

- 注册 IP；
- 最近登录 IP 与成功登录历史；
- API 调用 IP 聚合和事件历史。

用户管理中新增独立的“安全与 IP 审计”查看入口，不将敏感 IP 混入通用用户编辑接口。敏感查看必须写读取审计。

### 7.2 权限和时间范围

- 管理员：仅查看其管理范围用户的风险摘要、掩码 IP 和关联/异常计数。
- Root：查看完整 IP、完整历史、关联用户、注册/登录/API 调用时间线。
- IP 审计默认时间范围为近 30 天，可切换近 7 天、近 30 天、近 90 天、全部历史或自定义日期。
- IPv4 和 IPv6 分别标准化、聚合、筛选和展示，不将不同协议、网段或 IPv4 映射 IPv6 强行合并。
- IP 审计页面支持关联账号数和列表、调用/错误/登录次数、近期异常和最近活动。
- `c.ClientIP()` 的可信度依赖 `TRUSTED_PROXIES` 正确配置；审计页面应在配置异常时给管理员提示。

## 8. 游乐场聊天模式

### 8.1 顶层模式

游乐场仅有两个顶层模式：聊天和生图。两种模式在当前浏览器会话中独立保存草稿、模型和参数；切换不清空，刷新后不承诺持久化。

### 8.2 联网搜索和思考强度

联网搜索是聊天输入工具栏中的开关，不是顶层模式。用户可选关闭、basic、advanced，默认关闭。

1. 支持原生联网的模型/渠道透传兼容字段。
2. 不支持原生联网且 Tavily 启用时，调用 Tavily，按结果数和上下文长度裁剪后以带来源编号的事实参考上下文发送给模型。
3. 回答展示来源卡片；未配置、超时、无结果或失败时明确说明未注入搜索内容。
4. Tavily 使用内部 `SearchProvider` 抽象，第一版仅实现 Tavily。设置项包括 API Key、启用、默认深度、最大结果数、最大上下文长度和原生联网能力映射。
5. Tavily 请求必须有短超时、响应限制、脱敏错误和可观测日志，Key 不下发客户端。

聊天工具栏新增思考强度：关闭、低、中、高，默认关闭。仅对支持的模型/渠道显示或启用；后端映射为 `reasoning_effort`、预算或厂商字段并强制能力校验。

## 9. 游乐场独立生图模式

- 模型候选来自当前用户组可路由的图像生成 endpoint type，如 `dall-e-*`、`gpt-image-*`、`imagen-*`。
- 系统设置提供游乐场生图允许列表、禁用列表、显示排序和额外显式允许模型列表。
- 最终可见模型为用户可路由模型与系统允许模型的交集，按管理员排序；无模型时明确提示配置/分组问题。
- 生图调用既有 `POST /v1/images/generations`，不走 `/pg/chat/completions`。
- 表单包含提示词、模型、尺寸、生成数量、输出格式；质量、风格、背景/透明度仅在模型支持时显示和发送。
- 结果只保留当前浏览器会话：可预览、下载、复制 URL；URL 直接展示，Base64 仅转临时浏览器 URL；不写库、不创建永久图库。

## 10. 通用错误处理与安全边界

- 高权限、钱包、兑换码、Token、IP 审计等操作都在服务端进行权限、状态和幂等校验；前端隐藏不构成授权。
- 外部网络调用（Tavily、SMTP、头像图床元数据/确认等）设置连接、读取和总期限，继承取消语义，并返回脱敏错误。
- 所有金额和额度使用统一转换/舍入工具，避免裸浮点转整数。
- 头像只信任配置允许的第三方图床 URL；不允许用户提交任意地址。
- IP、邮箱、Token 标识、用户身份等个人/敏感数据按最小权限展示与脱敏。

## 11. 验收标准

### 权限与资料

- 仅 ID=1 可提升或降级其他 Root，其他 Root 不能变更 Root 角色，ID=1 不能降级自己。
- 普通用户只能改显示名称和头像；管理员及以上的用户名权限符合层级规则。
- 显示名称首次立即可改，之后服从默认 7 天且可配置的冷却期。
- 资料头部严格按 `@用户名 • 邮箱 • 角色 • 邀请人邀请码` 规则展示，没有缺失项的多余分隔符。
- 被封用户能看到用户可见理由，内部备注不泄露。

### Token、余额与兑换码

- 主余额等于钱包可消费额度，订阅不计入主余额。
- 自定义 Token 完整匹配且不按连字符截断；碰撞后旧 Token 被一次性禁用、通知和标记，外部不获知碰撞原因。
- 兑换码仅从钱包预扣；一次性码和拼手气红包正确领取、取消、过期退款，无重复扣款/退款。
- 用户仅能在“我的兑换码”管理自己的码；管理员用户兑换码入口遵循层级与审计。

### 邮件、日志和 IP

- 默认邮件模板始终可展示和回退；自定义模板可管理、预览、测试发送，变量校验正确。
- 绘图、任务、合规、来源归属四类记录都显示后端真实总计、服务端分页和每页行数选择。
- 管理员只能见掩码 IP 摘要；Root 可按可切换日期范围查看完整 IPv4/IPv6 明细和关联用户。
- 所定义的业务事件均有审计；静态资源和纯浏览不写业务审计库。

### 游乐场

- 原生联网优先，不支持时正确 Tavily 降级且展示来源；失败不虚报已联网。
- 思考强度默认关闭，仅向支持模型发送正确参数。
- 生图仅显示可路由且允许的模型，请求走图片生成接口，结果仅保留当前会话。

## 12. 验证策略

- Go 单元测试：角色矩阵、封禁理由、昵称冷却、用户名权限、Token 完整匹配/碰撞处置、兑换码领取/取消/过期退款、真实总计、IP 规范化和权限、模板回退、Tavily、模型参数映射。
- 集成测试：配置保存与运行时读取、管理 API 权限拒绝、审计事件、登录封禁反馈、兑换码事务、联网搜索降级、图片生成转发。
- 前端测试：资料头部、昵称/头像、用户管理、我的兑换码、管理员兑换码、四类日志分页/总计、IP 审计分级、模板、聊天工具栏、来源卡片、生图参数和会话画廊。
- 浏览器验收：桌面和较小视口下检查个人资料、钱包、管理员用户详情、IP 审计、日志、设置、聊天和生图的主要控件、加载/错误态、无横向裁切及可见性。
