# 运行态治理问题修复设计

## 目标

修复当前运行实例中已经复现的六类问题，并让界面展示、公开查询和真实业务执行共享同一套规则：

1. Playground 的思考档位必须真实影响上游请求，不能只改变界面状态。
2. IP 审计投影不能因部署节点是 slave 而永久停在加载中。
3. 邀请码界面去掉重复复制入口，缩减过高布局，并允许用户和管理员撤销有效邀请码。
4. 用户兑换码按站点标准额度创建，兑换动作只保留在钱包入口。
5. 分组订阅只能用于订阅授权的分组。
6. API Key 余额查询与真实扣费使用相同的分组订阅适用规则。

实现必须兼容 SQLite、MySQL 和 PostgreSQL；Default 与 Classic 前端保持业务语义一致；所有新增行为先用失败测试证明问题，再实现修复。

## 1. Playground 思考控制

### 1.1 协议语义

- `off` 是显式关闭请求，不再等同于“省略 `reasoning_effort`”。
- `low`、`medium`、`high` 是显式强度请求。
- Playground 后端只接受能够由当前模型和渠道可靠表达的档位。
- 不支持显式控制的模型或渠道不发送伪造参数；界面禁用思考菜单并显示“不支持调节思考”的本地化提示。
- 支持关闭但不支持全部强度档位的渠道只展示其真实支持的选项。

### 1.2 渠道适配

- OpenAI 兼容推理模型通过该协议支持的 `reasoning_effort` 值控制；若具体模型不接受关闭值，则该模型不声明关闭能力。
- Gemini 思考模型的关闭映射到现有 `-nothinking` / `thinkingBudget: 0` 适配路径，强度继续复用现有 thinking 配置。
- 使用模型名后缀表达思考能力的渠道，在 Playground 专用请求中由服务端生成适配后的上游模型名；客户端不自行拼接渠道后缀。
- DeepSeek 等模型只有在对应适配器能证明关闭语义时才声明关闭能力；模型天生强制推理时，界面明确不可关闭。

### 1.3 错误与审计

- 无效档位返回稳定的 400 业务错误。
- 模型或渠道不支持所选档位时返回稳定的“不支持”错误，不静默降级。
- 实际应用的思考档位写入现有 Playground 审计字段；未应用时不伪造成功记录。

## 2. IP 审计投影

### 2.1 Worker 启动策略

- 新增 `IP_SECURITY_PROJECTION_WORKER_ENABLED` 显式开关。
- 未设置时保持兼容默认：master 节点启用，slave 节点禁用。
- 设置为 true 时，任何具备主库和日志库写权限的节点均可运行 worker。
- 多节点并发由现有数据库租约保护；不能依赖 `NODE_TYPE` 作为唯一互斥机制。

### 2.2 过期租约恢复

- `running` 状态且 `locked_until` 已过期时，下一次 worker 循环必须能够重新取得租约并继续 backfill。
- worker 启动后立即执行一次投影，不等待首个重试周期。
- 完成 backfill 且无 pending event 后才将状态设为 `ready`。
- 投影失败保留最后错误和进度，下一轮重试继续处理，不把失败伪装成空结果。

### 2.3 API 和界面

- 投影未就绪时接口返回可识别的暂不可用错误。
- 前端显示明确状态、最后错误或“正在构建审计索引”，并提供重试按钮；禁止无限转圈后只显示笼统加载失败。
- readiness、worker 启停和租约恢复均有后端测试；运行实例必须验证状态最终进入 `ready` 且列表返回记录。

## 3. 邀请码撤销与布局

### 3.1 权限和状态

- 用户可撤回自己的 pending 申请，沿用现有 withdraw 接口。
- 用户可撤销自己名下的 active 邀请码；不能撤销他人的码或终态码。
- 任意 Admin 或 Root 可撤销任意用户的 active 邀请码，符合当前管理员统一管理规则。
- 撤销使用条件状态更新或行锁，重复请求收敛为同一终态，不重复写奖励或审计。
- 已被成功使用的历史记录保留；撤销只阻止后续注册，不回滚已经完成的邀请奖励。

### 3.2 API

- 本人入口新增 `POST /api/invitation/codes/:id/revoke`。
- 管理入口继续使用 `POST /api/invitation/admin/codes/:id/revoke`。
- Controller 只解析请求；对象所有权和管理员权限由 Service 强制执行。

### 3.3 界面

- 有效邀请码只保留一个主复制按钮，复制邀请码文本。
- 注册链接由二维码对话框内的明确次级动作提供，不再在主卡片放第二个相同图标按钮。
- 邀请激励区域改为紧凑的无嵌套卡布局，桌面和移动端都按内容自适应，不使用固定大高度。
- 用户和管理员列表均显示撤销动作、确认对话框和成功后的查询刷新。

## 4. 用户兑换码额度与统一兑换入口

### 4.1 额度单位

- 前端创建表单中的 `amount` 表示站点展示单位，而不是数据库原始 quota。
- 后端把展示单位乘以当前 `QuotaPerUnit` 后再写入 `total_quota`，并使用饱和、安全的 quota 转换工具。
- 新 API 优先接受明确的原始整数 `quota`；为兼容旧客户端，`amount` 仍可接受，但必须按展示单位转换。
- 最小份额按一个站点标准额度单位计算，不再使用原始 quota `1`。
- 所有金额校验和随机包分配都在转换后的整数 quota 上执行。

### 4.2 兑换入口

- `/user-redemptions` 仅用于创建、查看、复制、详情和取消本人创建的码，不再显示领取按钮或领取对话框。
- 钱包的“兑换码”输入框成为唯一兑换入口。
- 后端提供统一兑换服务：先按确定性规则识别管理员兑换码和用户兑换码，再调用各自现有事务逻辑；不能在前端依赖错误字符串猜测码类型。
- 同一码重复提交保持现有幂等和唯一领取约束，且只产生一次余额入账。
- 创建者取消、管理员取消和到期处理只退还尚未领取且尚未退款的 quota。

### 4.3 展示

- 创建表单、列表、详情和钱包统一使用站点额度格式化配置。
- 不把原始 quota 直接格式化成货币小数。
- Default 与 Classic 使用相同 API 语义，并补齐所有用户可见文案的翻译。

## 5. 分组订阅适用性

### 5.1 共享规则

新增不依赖 Gin 的 `service` 级订阅适用性模块。输入用户、实际请求分组和订阅，输出该订阅能否用于本次请求。

- `upgrade_group` 为空的历史订阅保持不限组兼容。
- 非空时仅适用于该组及 `GroupSpecialUsableGroup` 为该组显式添加的授权子组；全局可用组不会自动扩张订阅范围，`-:` 删除规则优先。
- 固定分组 Token 使用固定组判断。
- 空 Token 分组使用用户当前默认组。
- `auto` Token 使用当前 distributor 允许的候选组；一份订阅命中多个候选组时只计一次。
- 分组规则解析失败时按不可用处理并返回可审计错误，不能放宽为全组可用。

### 5.2 真实扣费

- `NewBillingSession`、活跃订阅检查、钱包回退判断和订阅预扣都接收同一个实际请求分组上下文。
- 模型层继续负责事务、锁、周期重置和额度扣减；服务层负责提供分组 eligibility。
- `subscription_first` 只有匹配当前分组的订阅才能阻止或允许钱包回退。
- `wallet_first` 在钱包不足时只能尝试匹配当前分组的订阅。
- 单次请求仍必须由一个资金来源完整覆盖，不能拼接多份订阅。

## 6. API Key 余额查询一致性

- `BuildTokenBalanceSnapshot` 使用与真实扣费完全相同的有效分组解析和订阅筛选函数。
- 余额快照只聚合对该 Key 当前分组范围有效的 active subscription。
- 固定组、默认组和 `auto` 候选组按既有设计返回准确限制信息。
- 订阅累计可用、单次上限、钱包回退和四种资金偏好必须与真实预扣结果一致。
- 响应继续脱敏 API Key，不返回用户资料、订阅 ID 或未参与资金来源。

## 7. 国际化与界面错误

- 本轮触及的 Playground、IP 审计、邀请码、用户兑换码、钱包、订阅和余额查询文案全部经过 Default 与 Classic 的 i18n 扫描。
- 枚举值和服务端错误码在前端映射为翻译键；不直接展示 `running`、`unsupported` 等裸英文状态。
- 页面失败必须有可重试或可纠正的下一步，不能只显示 500 或永久 spinner。

## 8. 测试与验收

### 8.1 测试先行

每项先新增最小失败测试并确认失败原因正确，再写生产代码：

- Playground payload、后端验证和渠道适配测试。
- IP worker 环境开关、slave 启动、过期租约恢复和 readiness 测试。
- 邀请码本人/管理员撤销、越权和重复撤销测试。
- 用户兑换码标准额度转换、统一兑换、重复领取和退款测试。
- 订阅本组、授权子组、拒绝组、空历史组、四种计费偏好测试。
- Token 余额快照与真实预扣一致性测试。
- Default 与 Classic 的交互、状态和 i18n 测试。

### 8.2 自动化门槛

- 相关 Go 包测试先通过，再运行 `go test ./...`。
- Default 运行相关 Bun 测试、typecheck、lint 和 production build。
- Classic 运行相关 Bun 测试、lint/i18n 检查和 production build。
- 使用 MySQL 容器执行资金、订阅、邀请和 IP 投影核心集成测试；SQLite 基线测试必须保持通过。

### 8.3 运行态门槛

- 从当前源码重建本地 QA 镜像并启动容器。
- 使用 QA 账号完成用户、Admin/Root 权限流程，不触碰主库业务数据。
- 用浏览器验证桌面和移动视口，检查网络响应、控制台错误、加载状态、重复按钮和布局高度。
- IP 投影状态必须从非 ready 收敛到 ready，IP 审计接口返回实际记录。
- 创建一个标准额度用户兑换码后，数据库 quota、列表显示、钱包兑换和余额变化必须一致。
- 创建不同分组订阅和 Token，证明非授权组真实请求不可消费该订阅，余额查询也不计入该订阅。

## 非目标

- 不改变已经完成的邀请奖励历史。
- 不允许管理员读取用户完整 API Key。
- 不通过前端隐藏代替后端对象权限。
- 不对不支持思考控制的模型伪造关闭能力。
- 不执行真实支付、OAuth、邮件发送或付费上游模型请求。
